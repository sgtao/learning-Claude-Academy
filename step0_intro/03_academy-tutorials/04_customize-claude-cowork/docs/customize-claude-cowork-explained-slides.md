## 多くの人は、==この順==で整える
lead: 一度整えれば、以降のタスクは「システムが接続され、チームのプロセスが組み込まれた状態」から始まる
```steps
style: cards
items:
  - icon: "🔌"
    title: コネクタ
    desc: Slack や Jira など、仕事のシステムにつなぐ
  - icon: "📝"
    title: 指示
    desc: 全タスク共通のルールを書く（トーン・書式など）
  - icon: "🧩"
    title: Skill
    desc: 同じタスクを何度か実行した後に作る
  - icon: "📦"
    title: プラグイン
    desc: コネクタと Skill のセット。管理者が各職種に配る手段
    tone: outline
```
point: 本文の目安は「まずコネクタと指示から」。Skill は繰り返してから、聞かれたら共有する
note: 根拠: 原本の見出しより前の本文（目的・コネクタ・指示・Skill・プラグインの説明）と、見出し「プラグインの例」の節の「多くの人は、まずコネクタと指示から始め…」の段落。解説メモ 02「3. セクション別の解説」。
note: 足した情報なし。順序は原本のとおりで、本文には所要時間（分）も有料プランの条件も書かれていない。

## コネクタは、読むだけでなく==書き込み==もできる
lead: 仕事のシステムに Claude をつなぎ、文脈と実行する力を与える
- **つなぐ先の例**：Slack、Salesforce、Microsoft 365、Jira、社内独自のツール
- **できること**：チケットの更新、返信の下書き作成、チャンネルへの投稿、ファイルの保存
- **有効にする場所**：左サイドバーの「カスタマイズ」パネル
- **認証**：一度認証すれば、その後どのセッションでもそのツールを使える
point: 書き込みもできるので、任せる操作を決めてから有効にする
note: 根拠: 原本の見出しより前の本文（コネクタの段落と「左サイドバーのカスタマイズパネルから…」の段落）。解説メモ 02「3. セクション別の解説」（A）・11 FAQ 2〜3。
note: 【補足】point の「任せる操作を決めてから有効にする」は、解説メモ 02「4. ユースケース」の筆者（AI）の助言で、本文には書かれていない。
note: 管理者以外がコネクタを有効にできるかなどの権限の条件は、本文には書かれていない。

## 指示は、==3つの層==で重なる
lead: Claude の作業のしかたを決める標準ルール（トーン・書式・確認するソース・従う規則）
| 層 | 適用される範囲 | 編集する場所 |
|---|---|---|
| グローバル指示 | 実行するすべてのタスク | 設定の「グローバル指示」（バージョンによっては「Claudeへの指示」） |
| プロジェクト指示 | そのプロジェクト内でのみ、グローバル指示に加えて | プロジェクトの右パネルの「指示」 |
| 組織の指示 | あなたの会話・タスク・Code の全体 | エンタープライズユーザーで、管理者が組織の設定を行うことがある |
point: 一般的なルールは指示に、繰り返し行うプロセスは Skill に入れる
note: 根拠: 原本の見出しより前の本文（指示の段落、グローバル・プロジェクト・組織の 3 項目、「一般的なルールは指示に…」の文）。解説メモ 02「3. セクション別の解説」（A）・11 FAQ 4〜6。
note: 本文は「次の2つのレベル」と書いたあとに番号付きで 3 項目を並べている。理由は本文から分からない。組織の指示は管理者の設定だから、という説明は解説メモの【推測】。

## Skill は、==普段の作業を通してから==作る
lead: 使うときは /skill-name で名前を指定するか、タスクを平易な言葉で説明する
```steps
style: circled
items:
  - title: 一通り実行する
    desc: 普段どおりにワークフローを最後まで行う
  - title: 最後に Claude に頼む
    desc: Skill にするよう依頼する（頼む文面は本文に無い）
  - title: 次回は 1 つのプロンプト
    desc: 組み込みの skill-creator が手順・テンプレート・ソースの所在を記録する
```
point: 同じタスクを何度か実行した後に作る人が多い
note: 根拠: 原本の見出しより前の本文（Skill の段落、「Skillを使用する」「Skillの作成」の段落、skill-creator の文）と、見出し「プラグインの例」の節の「多くの人は…」の段落。解説メモ 02「3. セクション別の解説」・11 FAQ 7〜8。

## プラグインは、==職種ごとのセット==
lead: Anthropic が、コネクタと主要ワークフロー向けの Skill をペアにして公開している
| 職種 | 本文に挙がる接続先 | 本文に挙がる Skill |
|---|---|---|
| セールス | HubSpot、Close、Clay、ZoomInfo、Fireflies（Slackも含む） | アカウント調査、商談準備、パイプラインレビュー、競合バトルカード |
| プロダクト | Atlassian（JiraとConfluence）、Linear、Notion、Slack | フィードバックのクラスタリング、PRD作成、スプリント更新、競合分析 |
| リーガル | Box、Egnyte、DocuSign、Slack、Atlassian | 契約レビュー、NDAのトリアージ、署名リクエスト、ベンダーチェック |
| オペレーション | Jira、Asana、Notion | ベンダーレビュー、プロセス文書化、変更リクエスト、キャパシティプランニング |
point: 自分の職種が無いときは、サイドバーで閲覧するか、自作して共有する
note: 根拠: 見出し「プラグインの例」の節（4 職種の列挙と「サイドバーで利用可能なプラグインを閲覧するか…」の文）。解説メモ 02「3. セクション別の解説」（B）・11 FAQ 9〜10。

## セットアップ後は、==自動化と見える化==へ
lead: 本文は、整えた道具の次の使い方として 2 つの追加機能を挙げる
- **スケジュールされたタスク**：設定した時刻にプロンプトを実行する。書いた Skill を毎週平日の午前 9 時に実行させる例が挙がる
- **Artifacts**：セッションをまたいでサイドバーに残るダッシュボード・トラッカー・比較ビュー
- **更新のしかた**：いつでも開き、コネクタからの最新データで Claude に更新させる
- **共有の手段**：チームメンバーに聞かれたら Skill を共有。プラグインは管理者が組織の標準セットを各職種に配る手段
point: 追加機能は、コネクタと Skill が整ってから
note: 根拠: 見出し「プラグインの例」の節の後半（スケジュールされたタスク、Artifacts、「多くの人は…」「プラグインは、管理者が…」）。解説メモ 02「3. セクション別の解説」（B）・11 FAQ 11〜12。
note: 【補足】point の「整ってから」は、本文の「セットアップが完了したら」の言い換え。本文に操作手順は書かれていない。

## 持ち帰る教訓と、次の 1 歩
1. **整えるのは一度でよい**：コネクタと指示を整えれば、以降のタスクは接続済み・ルール込みで始まる
2. **使い分けの軸は 2 つ**：全タスクに効くルールは指示、繰り返すプロセスは Skill
3. **順番が大事**：まずコネクタと指示、Skill は同じタスクを何度か実行してから
> 次の 1 歩：自分の仕事 1 件で、コネクタを 1 つ有効にし、グローバル指示を 1 行だけ書いて、いつもの作業を試す
note: 根拠: 解説メモ 02「3. セクション別の解説」「4. ユースケース」。教訓 1〜3 は原本の見出しより前の本文と「プラグインの例」の節の内容の整理。
note: 【補足】「次の 1 歩」の具体案（コネクタ 1 つと指示 1 行）は、解説メモ 02「4. ユースケース」の筆者（AI）の補足で、本文には書かれていない。
