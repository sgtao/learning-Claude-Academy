## 解説
### 1. 要約
このチュートリアルは、Claude に何度も説明している仕事のやり方を Skill にまとめ、会話のたびに自動で使わせる方法を教える。Skill は Projects やカスタム指示と役割が違う。Projects は資料や履歴がたまる作業の場で、その中にしか文脈が無い。カスタム指示は Claude 全般への好みである。Skill は特定の種類の作業に使う詳しい手順で、どの会話でも関連するときだけ働く。作るときは、形式を名指しし、トーンを設定し、良い例を 1 つ貼る。作ったら新しい会話で頼み、Skill が読み込まれたか、例と並べて構造と文体が同じかを確かめる。結論は、同じ 3 つを 2 回名指ししたら Skill にまとめる時だということである。

### 2. 例え話
【補足】Skill は「自分専用の作業マニュアルを、引き出しに入れておく」ことに似ている。毎回新人に口で説明する代わりに、形式・口調・見本を 1 冊にまとめて渡しておけば、依頼の内容が合うときに、新人が自分で引き出しから取り出して使う。Projects は「案件ごとの作業部屋」で、その部屋の中の資料はほかの部屋では使えない。

### 3. セクション別の解説
#### 1. 全体（分割なし）
- 本文には見出しが無いので、全体を 1 つのセクションとして扱う
- 前半：Skill を作る意味。うまくいった作業で自分がした「基準の説明・構成の記述・例の提示・修正」を、毎回やり直さずにまとめる
- 中盤：Skill・Projects・カスタム指示・プロンプトの使い分けと、Skill を作る場面（繰り返す手順、専門知識を束ねる作業、たまにしか行わない複雑な作業）
- 後半：利用できるプランと設定、始め方、自分の Skill の説明のしかた（形式・トーン・例）、確かめ方、習慣
- **根拠**：全体（分割なし）の節「Skillを作成することは、記述する行為です。」
- **根拠**：全体（分割なし）の節「Skillsはどこでも機能します。」
- **根拠**：全体（分割なし）の節「同じタスクに対して同じ3つのことを2回名指ししていることに気づいたら、それがSkillにパッケージ化するべきタイミングです。」

### 4. ユースケース
- 手順を再現する場面：毎週の更新、顧客の声の分析、営業の通話の準備、リサーチの整理など、何度も同じ説明をしている仕事
- 前提の環境：Free・Pro・Max・Team・Enterprise のどれかのプランで、コード実行とファイル作成が有効になっていること
- つまずく所：Skill が読み込まれない（名前や説明がタスクと合っていない）、出力が例と違う（Skill の文を直す）
- **根拠**：全体（分割なし）の節「Skillsは、Free、Pro、Max、Team、Enterpriseの各プランで利用できます。」

### 5. 理解を深める質問
#### 質問1：Skill・Projects・カスタム指示は、それぞれどんな仕事に向いているか
- **要点**：3 つの使い分け
- 回答：Skill は繰り返す手順をどの会話でも自動で使う。Projects は文脈がたまる作業（製品ローンチ、リサーチ、キャンペーン）の場。カスタム指示は Claude 全般への好み
- 解説：本文は「繰り返し可能な手順にはSkills」「蓄積されたコンテキストが必要な作業にはプロジェクト」「両方が要る作業には併用」と分けている。プロジェクトに上げた文脈は、そのプロジェクトの中にしか無い

#### 質問2：自分の仕事のうち、Claude に 2 回以上説明したことがあるものは何か
- **要点**：2 回説明した作業
- 回答：本文は、同じ説明を何度もしている作業を選ぶよう勧める。レポートの構成、分析の枠組み、顧客への連絡の文体が例に挙がっている
- 解説：【補足】自分の仕事での答えは本文には無いので、自分で書き出す。2 回以上説明した作業があれば、Skill にまとめる候補である

#### 質問3：Skill を作るとき、Claude に渡す 3 つのことは何か
- **要点**：渡す 3 つのこと
- 回答：形式を名指しする、トーンを設定する、良い例を 1 つ貼る、の 3 つ
- 解説：形式は「3 つのセクション、各 3 つまでの箇条書き」のように埋める形を渡すこと。トーンは誰がどう読むかを伝えること。例は、満足できた実際の出力で、説明より多くを伝えるとある

#### 質問4：Skill が働いたかどうかは、どう確かめるか
- **要点**：働いたかの確かめ方
- 回答：新しい会話で普段どおり頼み、Claude の思考モードに Skill の読み込みが出るかを見る。次に、結果を貼り付けた例と並べて、構造と文体が同じかを見る
- 解説：読み込みが出ないときは、タスクと Skill の名前・説明が合っていないので、どちらかを直すか、Skill の名前を言って頼み直す。手で直したくなる所は、Skill に書き足す

#### 質問5：Skill を使う前に、プランと設定で確かめることは何か
- **要点**：使う前の確認
- 回答：利用できるプランは Free・Pro・Max・Team・Enterprise。コード実行とファイル作成を有効にする。Free・Pro・Max は Settings > Capabilities、Team・Enterprise は組織の Owner が管理する
- 解説：Team・Enterprise では、Organization settings > Plugins & skills の Policy タブで、この設定と Skills の両方を管理する。【補足】自分のプランの表示は、使う前に画面で確かめる

## テーマ：Skill で仕事の進め方を渡す
### 背景
- うまくいった作業では、自分が基準・構成・例を示し、ずれを直している。その学びを毎回やり直さずまとめるのが Skill（全体（分割なし）の節「Skillを作成することは、記述する行為です。」）

### キー概念
- Skill：作業のやり方をパッケージ化したもの。関連する依頼のときに自動で読み込まれる
- 3 つの名指し：形式・トーン・良い例（全体（分割なし）の節「形式を名指しする。」）
- Projects との違い：Projects の文脈はそこにしか無い。Skill はどこでも使える（全体（分割なし）の節「Skillsはどこでも機能します。」）
- カスタム指示との違い：Skill は詳しい内容を持て、特定の作業にだけ働く

### 詳細解説
| 道具 | 向く仕事 | 範囲 |
|---|---|---|
| プロンプト | 一度だけの作業・探索 | その会話 |
| カスタム指示 | Claude 全般への好み（確認の質問をする、簡潔に） | すべての会話 |
| Projects | 文脈がたまる作業（製品ローンチ、リサーチ、キャンペーン） | そのプロジェクトの中 |
| Skill | 繰り返す手順（ブランド基準、分析の枠組み、レポート形式） | どの会話でも、関連するときだけ |

- 作る流れ：2 回以上説明した作業を選ぶ → 形式・トーン・例を 1 つのメッセージで Claude に説明する → 新しい会話で頼んで確かめる
- 始め方：Customize > Skills の Discover から事前構築済みの Skill を追加できる。Claude に頼んで Skill を作らせる方法もある
- 本文の例：週次チーム更新（成果・障害・優先事項、各 3 つまで）を Claude に説明して Skill にする

### 注意点・限界
- 所要時間は本文に書かれていない
- 本文の例は例であり、自分の形式・トーン・例に置き換える必要がある
- 利用できるプランと、コード実行・ファイル作成の設定は、使う前に自分の画面で確かめる
- 画面の表記は変わりうる【推測】

### ポイントまとめ
2 回説明したら Skill にする。形式・トーン・例の 3 つを渡し、新しい会話で確かめる。

### 確認の質問
自分の仕事で、形式・トーン・良い例の 3 つを名指しできる作業は何か。

## 活用案
### 案1：毎週の定型の文書を Skill にする
毎週作っている報告や更新（週次の連絡、議事録のまとめなど）を 1 つ選び、形式（セクションの数と箇条書きの上限）、トーン（誰がどう読むか）、満足できた過去の出力を 1 つ、Claude に 1 つのメッセージで説明して Skill にする。翌週、新しい会話で素材のメモだけ渡して頼み、Skill が読み込まれたかと、例との構造・文体の差を確かめる。手で直した所は Skill に書き足す。【補足】最初の 1 件は短い文書が試しやすい。（203字）

### 案2：Projects と Skill を役割で分ける
今使っている Projects の指示を見直し、「案件の資料や履歴」と「毎回同じ手順」に分ける。前者は Projects に残し、後者（レポートの形式や分析の枠組み）は Skill にして、どのプロジェクトや通常の会話でも使えるようにする。分けたあとは、新しい会話と Projects の中の会話の両方で同じ依頼をして、同じ形式で出るかを比べる。【補足】分け方の基準は本文の「繰り返す手順は Skill、蓄積する文脈は Projects」。（210字）

### 案3：説明の 2 回目で記録する習慣を作る
Claude に同じ形式・トーン・良い例を説明するたびに、その回数をメモに残す。同じタスクで 2 回目になったら、その日のうちに Skill にまとめる。月の終わりに、作った Skill を数えて、各 Skill が読み込まれた会話を 1 つ見直し、名前や説明が依頼と合っているかを直す。【補足】数や頻度の目標は本文には無いので、自分で決める。（161字）
