## Claude.ai は「一つの方法」にすぎない
lead: 同じ Claude を、すでに働いている場所の中で使う、という考え方
- **出発点**：Claude は知性であり、Claude.ai はそれを活用する一つの方法にすぎない
- **専門ツール**：働いている場所に合わせて設計された、いくつかのツールでも使える
- **このレッスンの狙い**：特定のワークフローやユースケースに合わせた追加の方法を紹介する
- **紹介の形**：多くのツールに「使用すべき場面」の箇条書きが付く
point: 先に「自分がいつも作業している場所」を決めると、選ぶ手がかりになる
note: 根拠の出典: 原本は見出しなし（本文冒頭の 2 段落）。解説メモ「1. 要約」「3. セクション別の解説」。point の一文は【補足】（出典: 02_explanation_memo.md「4. ユースケース」、11_question_and_answer.md FAQ 8）。

## 開発とチームの場所：Claude Code と Claude Tag
lead: 開発の作業場所と、Slack の中で動く
- **Claude Code**：ターミナル・IDE・ブラウザ・Slack で動くエージェント型コーディングツール
- **Code の場面**：機能構築、デバッグ、不慣れなコードベースの理解、lint エラー修正などの自動化
- **Claude Tag**：Slack に Claude を取り込み、スレッド内でタグ付けして使う
- **Tag の場面**：返信の下書き、長いスレッドの要約、会議準備、オンボーディング
- **つながり**：バグ報告の議論から、Claude Code セッションを立ち上げることもできる
note: 根拠の出典: 原本は見出しなし（本文の「Claude Code」「Claude Tag」の紹介部分）。解説メモ「3. セクション別の解説」・05 テーマ「キー概念」。補足の追加なし。非エンジニアが Claude Code を直接使う場面は本文には書かれていない（02_explanation_memo.md 質問 3 の回答）。

## Claude Design：アイデアを動くプロトタイプに
lead: 欲しいものを平易な言葉で説明する、またはスケッチやスクリーンショットから始める
- **何をするか**：アイデアを、実際に動作するインターフェースに変える
- **出てくるもの**：インタラクティブなプロトタイプ（アーティファクトとして構築）
- **その後**：直接編集する、チームと共有する、Claude Code に渡して構築させる
- **使える場所**：Claude とのあらゆる会話、Artifacts タブ、claude.ai/design
- **場面の例**：文章のブリーフからコードを書かずに UI プロトタイプへ進めたいとき
note: 根拠の出典: 原本は見出しなし（本文の Claude Design の段落と「使用すべき場面」）。解説メモ「3. セクション別の解説」・11_question_and_answer.md FAQ 4。補足の追加なし。本文では Design の名前が見出しでなく説明文の書き出しに入っている（変換で見出しが失われた可能性。解説メモ 05「注意点・限界」の推測）。

## Microsoft の 4 アプリ：サイドバーで Claude を使う
lead: 本文では Claude for Excel・PowerPoint・Word・Outlook が個別に紹介される
- **Excel**：数式の理解、前提条件の更新、#REF! などのエラーのデバッグ、チャート作成
- **PowerPoint**：アウトラインから初稿、文章の引き締め、構成の見直し、書式の統一
- **Word**：初稿の作成、セクションの修正、コメント・変更履歴への対応
- **Outlook**：メールの仕分け、返信の下書き、長いやり取りの要約と次のステップのリスト
point: 4 つはどれも、開いているアプリの横で会話しながら頼む形

## Claude in Chrome：ブラウザの中で使う
lead: Chrome にサイドバーとして追加するブラウザ拡張機能
- **できること**：取り組んでいる作業を観察し、ブラウザ内で直接アクションを実行する
- **場面 1**：ブラウジング中に記事・研究論文・ウェブページを要約する
- **場面 2**：繰り返しの多いフォーム入力を自動化する
- **場面 3**：複数ステップのワークフローを、手でクリックせずに進める
- **場面 4**：タブやタスクを移動してもコンテキストを保つ。社内ツール・CRM・ダッシュボードにも向く
note: 根拠の出典: 原本は見出しなし（本文の Claude in Chrome の段落と「使用すべき場面」）。解説メモ「3. セクション別の解説」・11_question_and_answer.md FAQ 6。補足の追加なし。

## なぜそう言えるか、何が分からないか（Why So）
lead: 本文から言えることと、本文には書かれていないことを分けて確かめる
- **言える**：どのツールも「動作する場所」が中心に書かれている（表の列がその形）
- **言える**：「使用すべき場面」は、下書き・要約・修正・自動化・デバッグという仕事の動詞で書かれている
- **書かれていない**：非エンジニアが Claude Code を直接使うかどうか
- **書かれていない**：Claude Cowork 以外のツールのプラン・料金・権限の条件（要確認: 各ツールの案内ページや職場の管理者）
- **偏りの点検**：「便利そう」で選んでいないか。自分の作業場所に当たるか
note: 根拠の出典: 原本は見出しなし（本文の比較表と各ツールの段落）。解説メモ 06 総括「横断分析」・05「注意点・限界」・03 質問 3・4 の回答。「偏りの点検」の一行は自己学習用の補足（出典: 02_explanation_memo.md「5. 理解を深める質問」を元にした問いの形。スキルの目的 A の観点）。リンク先の中身は解説メモでも読んでいない。

## 教訓と、次に試す 1 つ
lead: 読んだあとに、自分の仕事 1 件で試せる形にする
1. **教訓**：Claude に会いに行くのでなく、自分がいつも作業している場所に来てもらう
2. **選び方**：表の「動作する場所」から、毎日開いている場所に近い行を選ぶ
3. **試し方**：そのツールの「使用すべき場面」から、いま抱える仕事に近い項目を 1 つ選んで頼む
4. **確認**：使えるかどうかは、自分のプランと職場の管理者の設定で確かめる
5. **次の 1 つ**：1 件頼んだら、結果と手間を書き留め、頼み方を 1 回だけ直してみる
point: 次にやること：自分の「いつもの場所」を 1 つ決める
note: 根拠の出典: 解説メモ 06 総括「一言まとめ」、02「4. ユースケース」、07 活用案、03 質問 5 の回答。2〜5 の具体的な手順は【補足】（出典: 02_explanation_memo.md「4. ユースケース」と「活用案」。原本には書かれていない）。原本の比較表の列名「動作する場所」と、各ツールの「使用すべき場面」は原本のとおり。
