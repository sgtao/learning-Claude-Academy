## アーティファクトとは：チャットに埋もれない成果物
lead: Claude と一緒に作る成果物。会話と並んだ専用ウィンドウで形になる
- **成果物の種類**：ドキュメント、プレゼンテーション、デザイン、ダッシュボード、プロトタイプなど
- **専用ウィンドウ**：実際の成果物が形になっていく様子を見て、すぐ使ったり調整したりできる
- **作られるとき**：それ自体で完結し、編集・再利用・共有したくなるものを求められたとき
- **確実に作らせるには**：「これをアーティファクトとして作成して」と伝えるだけでよい
point: 長いコードや文章のブロックの代わりに、使える成果物を受け取る
note: 根拠：本文（見出しなし）の冒頭 2 段落（「会話と並んだ専用のウィンドウで実際の成果物が形になっていく様子を確認でき」など）。解説メモ 02「3. セクション別の解説」に対応。
note: 補足を足していない箇所。例え話（作業台つきの工房）は筆者（AI）の補足で、解説メモ 02「2. 例え話」にある。スライド本文には載せていない。

## 作り方は 2 通り：専用の方法と、会話内の作成
lead: ビジュアル・プレゼン・共同編集の文書には専用の方法がある
| 方法 | 作るもの | 特徴 |
|---|---|---|
| Claude Design | ランディングページ、1ページ資料、製品モックアップ、プロトタイプ | デザインシステムを取り込める。キャンバス上で直接編集 |
| Claude Slides | プレゼンテーション | メモやレポートを共有すると、構成・執筆・レイアウトまで Claude が行う |
| Claude Docs | 共同編集ドキュメント | 同僚と同時に編集。チャートや図はスナップショット |
| 会話内で作る | チャート、フローチャート、インタラクティブなページ、動くコード | Free を含むすべてのプランで利用できる |
point: 3 つの専用の方法は 1 つの会話で連携でき、一方から他方を作ってもらえる
note: 根拠：本文（見出しなし）「Claudeには、最も一般的な業務成果物それぞれを作成するための専用の方法があります」以降の 3 項目と、「Freeを含むすべてのプランで利用できます」。解説メモ 05「詳細解説」の表に対応。
note: Pro・Max で Design・Slides・Docs が使えるかは、本文には書かれていない。表では触れていない。

  - icon: "🗂"

## 変更する方法は 3 つ（自由に組み合わせられる）
lead: 直接編集とコメントは、デザイン・プレゼンテーション・ドキュメントの体験の一部
- **直接編集する**：文書に入力、スライドを編集、キャンバス上の要素をドラッグしてサイズ変更
- **Claude へのコメント**：変えたい箇所にコメント。ドキュメントでは @メンションで変更の理由も返る
- **ただ頼む**：会話で話し続けると、Claude が次の修正を加え、すべての変更を見せてくれる
point: 誤字は自分で直せば、説明して書き直しを待つ必要がなくなる
note: 根拠：本文（見出しなし）「アーティファクトが存在すれば、それを変更する方法は3つあり、自由に組み合わせることができます」。解説メモ 05「詳細解説」の表に対応。
note: モバイルアプリでも編集できるが、共有相手の変更はデスクトップまたはウェブ版（本文のとおり）。3 つは順序ではないので、矢印のある手順の図にはしていない。

## 共有と持ち出し：初期は非公開、プランで扱いが違う
lead: 共有相手がアーティファクトを開くには、Claude アカウントが必要
| 項目 | 内容 |
|---|---|
| 初期状態 | 共有するまで非公開。名前またはメールで人を追加し、閲覧・コメント・編集から選ぶ（ドキュメントは閲覧と編集のみ） |
| Pro・Max | 自分だけのままか、リンクを持つ誰とでも共有かを選べる。共有されるのはアーティファクトのみ |
| Team・Enterprise | リンクは既定で組織内。外部共有は、Owner または Primary Owner が組織設定 > Artifacts で有効にした後にのみ |
| 持ち出し | プレゼンは .pptx・Google Slides・.pdf、デザインは .pptx・.pdf・.html、ドキュメントは Google Docs または .docx |
point: 共有する前に、相手と許す操作（閲覧・コメント・編集）を決めておく
note: 根拠：本文（見出しなし）「アーティファクトは、共有するまでは非公開です」以降の共有の段落と、「作業をClaudeの外に持ち出す必要がある場合は、エクスポートしてください」の段落。解説メモ 05「詳細解説」の共有・エクスポートの表。
note: 【補足】point の「相手と許す操作を先に決める」は、本文末尾の問いかけ「次の作業を誰と共有しますか」を受けた筆者（AI）の整理（解説メモ 03 の質問3）。有料プラン・権限の条件は本文のとおりに書いた。

## 依頼のコツ 5 つ：なぜそれが効くのか
lead: Why So（なぜそう言えるか）を、本文の理由づけと一緒に確かめる
- **成果物を頼む**：要約を頼むとチャットの返信、経営陣向けの 1 ページのドキュメントを頼むと共有して続けられるものになる
- **具体的に伝える**：入力項目・円グラフ・超過時の警告まで書いた予算トラッカーの依頼のほうが、良い結果になる
- **使う人を説明する**：新入社員向けかエンジニアリングチーム向けかで、デザイン上の選択が変わる
- **作業を土台にする**：Claude がすでに問題を理解している会話の終盤に、最良のものが生まれる
- **最新データは更新を頼む**：埋め込んだチャートや図は自動では更新されない
note: 根拠：本文（見出しなし）の太字 5 項目（「コンテンツだけでなく、成果物を依頼してください」「欲しいものを具体的に伝えてください」「エンドユーザーを説明してください」「すでに行った作業を土台にしてください」「最新のデータが必要なときは更新してください」）。解説メモ 11 の FAQ 10・11 に対応。
note: 補足を足していない箇所。理由づけは本文の説明を言い換えたもの。

## 教訓と、次に試す 1 つ
lead: 次のレッスンは Skills（Claude に専門的なワークフローを教える、再利用可能な指示セット）
1. **成果物として頼む**：チャットの返信ではなく、編集・共有して続けられるものとして頼む
2. **作る場所と置き場所を分ける**：会話で作り、Artifacts タブで育てる
3. **共有の前に、相手と許す操作を決める**：閲覧・コメント・編集のどれか
point: 次に試す 1 つ：自分が最もよく手作業で作る成果物を 1 件選び、使う人を添えて、アーティファクトとして頼んでみる
note: 根拠：本文末尾の問いかけ「あなたが最もよく手作業で作成している成果物のうち、代わりにアーティファクトとして始められるものは何でしょうか」と、「次のレッスンでは、Skillsについて学びます」。解説メモ 02「4. ユースケース」の目標に対応。
note: 【補足】3 つの教訓の言い回しと「次に試す 1 つ」の具体化は、解説メモ（筆者（AI）の整理）に基づく。本文は 3 つの問い（手作業の成果物・繰り返しの作業・共有相手と許す操作）を示している。
