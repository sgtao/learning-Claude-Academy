## 作業は==3つの形==に分類される
lead: 自分が今どの形にいるかを知ること。それがこのレッスンで身につけるスキルのすべて
- **ターンごとにやり取りする**：尋ね、答えが返り、方向づけ、修正する。思考はそのやり取りの中で起こる
- **作業を任せる**：成果を説明すると、Claudeが計画・実行して結果を持って戻る。自分は計画と出力のレビュー
- **Claude Codeでソフトウェアを構築する**：コードベース内で直接作業する。開発者向け
> 最初の2つは知識労働者が1日の大半を過ごす場所。3つ目は開発者の作業スペース
point: 身につけるのは「今どの形か」に気づくこと
note: 出典は原本の導入部（見出しなし）。解説メモ 02「解説」の「3. セクション別の解説」と README の概要。
note: 【補足】なし。ここまでは原本の記述のみ。

## 3つの形と、現在アプリのどこにあるか
lead: 新しいClaudeエクスペリエンスでは、ChatとCoworkの区別はなく、どの会話でも両方の作業ができる
| 形 | 向く場面 | 所在 |
|---|---|---|
| ターンごとにやり取りする | 答えで次の質問が変わる／過程に関わり続けたい／すぐ終わる | Chat |
| 作業を任せる | 複数ステップ／完成ファイルが必要な場所に置かれる／複数ツールにまたがる／スケジュール実行 | Cowork |
| ソフトウェアを構築する | コードベースでコードを書き、テストし、実行し、出荷する | Codeタブ |
point: 最初にタブを選ぶのではなく、作業の種類に気づくとタブがそれに従う

## Chat：==考えながら進める==作業
lead: 価値がやり取りそのものにある。まだ形になっていないアイデアや、うまくまとまらない段落を持ち込む
- **使うとき**：答えで次の質問が変わる／過程に関わり続けたい／すぐに終わる
- **例**：見慣れないダッシュボードをスクリーンショットで見せ、指標の意味を尋ね、フォローアップで気にすべきものに絞る
- **デスクトップならでは**：クイックエントリー(Mac)・スクリーンショットとウィンドウ共有(Mac)・音声入力(Mac)・デスクトップコネクタ
> 例：会議の合間に、音声で話してアウトラインを下書きしてもらう（4ターンで完了）
point: 「すぐ終わる」質問のために、タスク全体を設定するのは手間
note: 出典は原本の「これは思考のパートナーとしてのClaudeです」から始まる段落群（見出しなし）。解説メモ 11「FAQ」の4番・5番。
note: Mac の注記が付くのは3つの機能。Mac 以外の OS の対応可否は原本に書かれていない。

## Cowork：==成果を説明して==任せる
lead: 質問する代わりに、作業全体を渡す。自分は会話しているのではなく委任している
- **複数ステップ**：取り出し・比較・要約・整形が、4つの用事ではなく1つの指示になる
- **完成ファイルが必要な場所に置かれる**：リネーム済みファイル、正しいフォルダのスプレッドシートなど
- **複数ツールにまたがる**：会議メモ・Slack・スプレッドシートを、Claudeが自分で集める
- **スケジュールで実行**：金曜日のレビュー、月曜日の準備ブリーフィング
- **手は引かない**：範囲や形式の質問・計画の提示を経て、進捗を見守り方向づけできる。行動前に確認する設定なら、メール送信やファイル共有は承認待ちで止まる
point: 自分のデスクから出ていくものは、常に自分がコントロールしている
note: 出典は原本の「Claudeとエージェント的に働くことは…」から始まる段落群（見出しなし）。解説メモ 11「FAQ」の6番・7番。
note: 承認待ちで止まるのは、Claudeが行動前に確認するよう設定されている場合。どの操作が承認の対象になるかの一覧は原本に書かれていない。

## Coworkの7つの機能
lead: ローカルフォルダへのアクセスが、完成ファイルをダウンロードで返すChatとの具体的な違い
| 機能 | できること |
|---|---|
| ローカルフォルダ | 指定したフォルダを読み、完成した作業を同じ場所に保存し直す |
| スケジュールタスク | 設定した頻度で実行。リモート実行なのでスリープ中・アプリが閉じていても動く |
| サブエージェント | 大きな仕事を、独自のコンテキストを持つバックグラウンドワーカーに並行して分ける |
| プロジェクト | 関連タスクを、ファイル・指示・記憶を持つワークスペースにまとめる |
| ブラウザ使用 | Claude in Chromeでサイトを操作し、見つけたものをタスクに取り込む |
| コンピュータ使用 | コネクタが無いとき、クリックや入力、アプリを開く操作を直接行う |
| プラグイン | スキル・コネクタ・エージェントの既製バンドル。Customize → Pluginsから追加 |
note: 出典は原本の「現在の製品では。デスクトップアプリでは、Coworkでタスクを任せることができます」の箇条書き（見出しなし）。解説メモ 02 の「詳細解説」と 11「FAQ」の8番・9番。
note: スケジュールタスクは、コンピュータ上のファイルを使う場合はデスクトップアプリを開いたままにする。コンピュータ使用は、触れるアプリごとに許可を求め、立ち入り禁止にはブロックリストが適用される。

## Codeタブ：非エンジニアは==知っておく==だけでよい
lead: 開発者向けに作られているが、自分では一度も開かないとしても知っておく価値がある
- **位置づけ**：別のタブで、このコースでは必要ない。詳しくは Claude Code in Action で扱われる
- **できること**：コードベース内で読む・書く・テストする・コマンドを実行する。ビジュアル差分、組み込みターミナル、gitによるロールバック
- **場所を選ぶ**：ローカル（フォルダを直接操作）／クラウド（GitHubリポジトリを接続。アプリを閉じても継続）
- **自律度を選ぶ**：手動承認／編集を自動承認／プラン
point: 3つの形を区別できれば、Codeタブは「別の形」と覚えておける
note: 出典は原本の「コードを書く場合…」以降の段落群（見出しなし）。解説メモ 11「FAQ」の11番。
note: 【補足】point の「別の形と覚えておける」は筆者の整理（原本は「別のタブであり、このコースでは必要ありません」と述べる）。「知っておく価値」が具体的に何かは原本に書かれていない。リンク先の中身は読んでいない。

## 教訓と、自分への問い
1. **形を先に見極める**：今の依頼は、答えで次の質問が変わるか。複数ステップ・ファイル・複数ツール・スケジュールのどれかに当てはまるか
2. **任せても承認は自分が持つ**：メール送信やファイル共有など、重要なアクションを自分はどこで確認したいか
3. **習慣を疑う**：今週、習慣で一問一答にしていた依頼は、実は丸ごとのタスクではなかったか
> 自分への問い：最も手放したいタスクは、複数ステップか、ファイルの保存と整理が要るか、複数ツールにまたがるか
point: 次の1歩：手放したい1件を選び、最初に尋ねる質問ではなく、Claudeに説明する成果として書き出す
note: 出典は原本の末尾の問い（見出しなし）と、解説メモ 02「5. 理解を深める質問」・07「活用案」。
note: 【補足】問いの言い回しと、教訓の3つへの整理は、解説メモの整理に基づく。成果の書き方の型（何を・どの形式で・どこに保存してほしいか）は筆者の提案で、原本にはない。
