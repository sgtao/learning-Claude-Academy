## 解説
### 1. 要約
このレッスンは、Claudeデスクトップアプリでの仕事を「ターンごとにやり取りする」「作業を任せる」「Claude Codeでソフトウェアを構築する」の3つの形に分けます。ターンごとの作業はChat、任せる作業はCowork、ソフトウェアの構築はCodeタブで行います。最初の2つは知識労働者が1日の大半を過ごす場所で、3つ目は開発者の作業スペースです。身につけるのは、今の作業がどの形かに気づくことです。CoworkとCodeタブは利用できるプランが限られ、Chatの一部機能にはMac向けの注記があります。

### 2. 例え話
【補足】本文にはない例えです。Chatは同僚と机を並べて相談する時間、Coworkは仕事を依頼して完成品を受け取る時間、Codeタブは開発者が工房にこもって部品を組み上げる時間、と考えるとイメージしやすくなります。

### 5. 理解を深める質問
#### 質問1：今週Claudeをどのように使ったか。ターンごとの思考だったリクエストと、習慣で一度に一つの質問として投げていたが実は丸ごとのタスクだったリクエストは、それぞれどれか。
- **要点**：今週の依頼を、思考の形か丸ごとのタスクかで見分ける
- 回答：自分の今週の依頼を並べ、答えで次の質問が変わる・過程に関わりたい・すぐ終わるものはターンごとの作業（Chat）、複数ステップ・完成ファイルが必要・複数ツールにまたがる・スケジュール実行のものは任せる作業（Cowork）と見分ける。
- 解説：本文はChatの使いどころとして「答えによって次に尋ねることが変わる」「その過程に関わり続けたい」「すぐに終わる」を挙げ、Coworkの使いどころとして4つの条件を挙げている。本文末尾の問いは、習慣で一度に一つの質問として投げていた依頼が、実は丸ごとのタスクだったのではないかと気づくことを促している。どの依頼がどちらかは、読み手自身の今週の使い方による。本文には書かれていない。

#### 質問2：最も手放したいタスクは、複数ステップ・ファイルの保存と整理・複数ツールにまたがる、のどれに当てはまるか。当てはまるなら、Claudeに説明する成果をどう書くか。
- **要点**：手放したいタスクを成果として書き出す
- 回答：手放したいタスクが複数ステップ・コンピュータ上へのファイル保存と整理・複数ツールにまたがる、のいずれかに当てはまるなら任せる作業であり、最初に尋ねる質問ではなく、Claudeに説明する成果を書き出す。
- 解説：本文は、任せる作業では「あなたは成果を説明します」とし、例として完成した概要書、整形された成果物、毎週月曜日に実行されるタスクを挙げている。【補足】書き出し方の型（例：何を・どの形式で・どこに保存してほしいか）は筆者の提案で、本文にはない。

#### 質問3：作業を任せるとき、メールの送信やファイルの共有などの重要なアクションについて、自分の承認をどこに残したいか。
- **要点**：重要アクションの承認をどこに残すか
- 回答：メールの送信やファイルの共有などの重要なアクションは、Claudeが行動前に確認するよう設定されていれば、承認を待って停止する。自分が承認を残したい範囲は、この設定を前提に決める。
- 解説：本文は、作業を任せても手を引くわけではなく、範囲や形式を明確にする質問があり、計画が示され、進捗を見守りいつでも方向づけできると述べる。ただし、どの操作が承認の対象になるかの細かい一覧は本文には書かれていない。

#### 質問4：自分の利用プランと使っている環境では、Chat・Cowork・Codeタブのうち何が使えるか。本文だけでは分からないことは何か。
- **要点**：自分のプランと環境で使える範囲
- 回答：Coworkは本文に挙げられたPro・Max・Team・Enterpriseのユーザーが利用でき、Codeタブも同じ4つのプランで利用できる。Chatの一部機能にはMacの注記があり、コンピュータ使用はPro・Maxプランでリサーチプレビュー中である。
- 解説：自分のプラン名と使っているOSを、この条件と照らして確かめる。Windowsなど、Mac以外の対応可否は本文には書かれていない。【補足】最新の条件は変わりうるため、実際の画面や公式の案内で確かめるのが安全である。

#### 質問5：開発者ではない自分にとって、Claude Codeを「知っておく価値」はどこにあるか。
- **要点**：開発者でない自分にとってのClaude Codeの価値
- 回答：本文は、Claude Codeを開発者向けに作られているとしつつ、自分では一度も開かないとしても知っておく価値があると述べる。非開発者は、別のタブでありこのコースでは必要ない、と覚えておけばよい。
- 解説：知っておく価値が具体的に何かは、本文には書かれていない。【推測】三つの形を区別できることで、自分の作業がどの形にも当てはまらないソフトウェア構築なのかを見分けやすくなる、という意味合いが考えられる。詳しくは本文のリンク先（Claude Code in Action）で扱うとされているが、リンク先の中身は読んでいない。

## テーマ：Chat・Cowork・Codeの3つの形の使い分け
### 背景
Claudeデスクトップアプリは、仕事のホームベースとされる。作業を3つの形に分け、今どの形にいるかに気づくことがこのレッスンの核である。根拠：本文（見出しなし）「作業は3つの形に分類され、自分が今どの形にいるかを知ることこそが、このレッスンで身につけるべきスキルのすべてです。」

### キー概念
- ターンごとにやり取りする：思考がやり取りの中で起こる。現在の製品ではChat。
- 作業を任せる：成果を説明し、Claudeが計画・実行して結果を持って戻る。現在の製品ではCowork。
- ソフトウェアを構築する：Claudeがコードベース内で直接作業する。現在の製品ではCodeタブ。
- 新しいClaudeエクスペリエンスでは、ChatとCoworkの区別はなく、どちらの作業もどの会話でも行える。

### 詳細解説
| 形 | 現在の所在 | 向く場面（本文） | 主な機能（本文） | 条件（本文） |
|---|---|---|---|---|
| ターンごとにやり取りする | Chat | 答えで次の質問が変わる／過程に関わり続けたい／すぐ終わる | クイックエントリー(Mac)、スクリーンショットとウィンドウ共有(Mac)、音声入力(Mac)、デスクトップコネクタ | 本文に利用プランの記述なし |
| 作業を任せる | Cowork | 複数ステップ／完成ファイルが必要な場所に置かれる／複数ツールにまたがる／スケジュール実行 | ローカルフォルダへのアクセス、スケジュールタスク、サブエージェント、プロジェクト、ブラウザ使用、コンピュータ使用、プラグイン | Pro・Max・Team・Enterprise。コンピュータ使用はPro・Maxでリサーチプレビュー |
| ソフトウェアを構築する | Codeタブ | コードベースでコードを書き、テストし、実行し、出荷する | ビジュアル差分、組み込みターミナル、gitによるロールバック。ローカル／クラウド。手動承認・編集を自動承認・プラン | Pro・Max・Team・Enterprise |

- 因果関係：最初にタブを選ぶのではなく、作業の種類に気づくとタブがそれに従う。
- 任せるときの関わり方：範囲や形式の質問、計画の提示、進捗の確認、重要アクションの承認待ち。
- スケジュールタスクはリモートで実行されるためコンピュータがスリープでもアプリが閉じていても動くが、コンピュータ上のファイルを使うタスクはデスクトップアプリを開いたままにする。
- 実務での適用：今週の依頼を3つの形に振り分け、手放したい1件を成果として書き出して試す【補足】。

### 注意点・限界
- 冒頭の「6つの情報源」の内訳は本文に書かれていない。
- Mac以外のOSの対応可否は本文に書かれていない。(Mac)の注記はChatの3つの機能に付く。
- 「新しいClaudeエクスペリエンス」の定義・画面は本文に書かれていない。
- 本文のリンク先（Claude Code in Action、Cowork in the cloud）の中身は読んでいない。動画の字幕は取っていない。
- 【補足】機能名・プラン条件は変わりうる。本文も新しい機能が定期的に追加されると述べる。

### ポイントまとめ
今の作業の形（やり取り・任せる・構築）を見極め、Chat・Cowork・Codeタブを使い分ける。

### 確認の質問
自分が最近Claudeに頼んだ作業のうち、複数ステップ・ファイル保存・複数ツール・スケジュールの条件のどれかに当てはまるものは何か。

## 活用案
### 案1：実務の担当者の視点
週明けの朝、これまで毎回メッセージの確認とステータスのまとめを一問一答で頼んでいた作業を見直す。複数ステップで毎週同じなら、任せる作業の条件に当てはまる。完成物の形と保存先を成果として書き出し、Coworkのスケジュールタスクにできないか試す。【補足】成果の書き方（例：要点を並べた1枚のメモ）は筆者の例で、本文にはない。最初の1件だけ設定し、出てきた計画と出力を確認して、重要な操作の承認を自分が持つ形にする。（206字）

### 案2：学習者の視点
今週のClaudeへの依頼を5件書き出し、それぞれに「ターンごと」「任せる」「ソフトウェア構築」のラベルを付ける。迷ったものは、答えで次の質問が変わるか、複数ステップか、ファイルが必要か、複数ツールか、スケジュールか、の5つの問いで判定する。【補足】ラベルがばらつく理由を一言メモすると、自分の使い方の癖が見えてきます。自分のプランと環境で使える機能は、利用条件と照らして確認する。（191字）

### 案3：思考プロセスの視点
考えがまとまっていない段階はChatで一緒に考え、やることが決まってから成果として任せる、と段階を分けてみる。最初から全部を決めきれない依頼は、ターンごとの形が向く。逆に、答えが決まっている繰り返し作業を毎回ターンごとに頼むのは、手間のかけ方が合っていない可能性がある【推測】。依頼の前に一呼吸おいて、今はどの形かを自問する習慣をつける。（169字）
