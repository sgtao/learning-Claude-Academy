Claudeデスクトップアプリは、Claudeと仕事をするためのホームベースです — 会議中のちょっとした質問から、あなたが他のことをしている間にClaudeが6つの情報源からまとめ上げるレポートまで。作業は3つの形に分類され、自分が今どの形にいるかを知ることこそが、このレッスンで身につけるべきスキルのすべてです。

- **Claudeとターンごとにやり取りする。** あなたとClaudeが行き来します。あなたが尋ね、Claudeが答え、あなたが方向づけ、Claudeが修正します。思考はそのやり取りの中で起こります。
- **Claudeに作業を任せる。** あなたは成果を説明します — 完成した概要書、整形された成果物、毎週月曜日に実行されるタスクなど — すると、Claudeがそれを計画し、実行し、結果を持って戻ってきます。あなたは計画と出力をレビューするだけで、各ステップを自分でつなぎ合わせる必要はありません。
- **Claude Codeでソフトウェアを構築する。** Claudeはコードベース内で直接作業します。コードを読み、書き、テストし、コマンドを実行します。開発者向けに作られていますが、自分では一度も開かないとしても知っておく価値があります。

最初の2つは、ほとんどの知識労働者が1日の大半を過ごす場所であり、3つ目は開発者の作業スペースです。このレッスンの残りの部分では、その違いを具体的に示し、それぞれが現在アプリのどこにあるかを説明します。

**現在の製品では。** ターンごとの作業はChatで行われます。任せる作業はCoworkで実行されます。ソフトウェアの構築はCodeタブで行われます。この3つはすべてClaudeデスクトップアプリの中にあります。新しいClaudeエクスペリエンスをご利用の場合、ChatとCoworkの区別はありません。どちらの種類の作業も、どの会話でも行えます。

これは思考のパートナーとしてのClaudeです。価値がやり取りそのものにある作業の形です。まだ形になっていないアイデア、見慣れないダッシュボード、うまくまとまらない段落などを持ち込み、一度に一つずつ、一緒に解決していきます。

**こんなときに使う:**

- **答えによって次に尋ねることが変わる。** ブレインストーミング中で、それぞれの応答が次の質問を開きます。まだわかっていなかったので、最初からリクエスト全体を書くことはできませんでした。
- **その過程に関わり続けたい。** 下書き、編集、声に出して考えること — ポイントは最後にできあがるものではなく、毎回のターンでのあなたの判断です。
- **すぐに終わる。** 質問、書き直し、「これはどういう意味?」といったもの — タスク全体を設定するのはかえって手間になるほど小さなものです。

**試してみる場面:**

- 見慣れないダッシュボードを見つめているとき。スクリーンショットを撮って「これらの指標は何を意味していますか?」と尋ねます。ダッシュボードを表示したままClaudeが説明し、あなたのフォローアップ(「では、実際に気にすべきなのはどれですか?」)が次のターンになります。
- 会議の合間にプレゼンテーションの構成を考える必要があるとき。音声で話して説明し、Claudeがあなたの発言からアウトラインを下書きします。セクション3に異議を唱えると、修正されます。4ターンで、次の通話の前に完了します。
- 何週間もApple Notesに製品ローンチのアイデアを書き留めてきたとき。Claudeにローンチに関するすべてをまとめてもらい、中途半端なまま残していたものを見つけ出し、他の接続済みツールで抜け漏れがないか確認してもらいます。そして、その抜け漏れを一緒に埋めていきます。

**現在の製品では。** デスクトップアプリではこれがChatです — claude.aiでおなじみのClaudeと同じものに加え、コンピュータ上でネイティブに動作することによるいくつかの機能が加わっています。

- **クイックエントリー。** Optionキーをダブルタップ(Mac)すると、作業中の画面の上にClaudeを呼び出せます。アプリを切り替えても最前面に表示されるコンパクトなウィンドウで応答します。
- **スクリーンショットとウィンドウ共有。** スクリーンショットを撮るか、ウィンドウを共有することで、Claudeがあなたの見ているものを見られるようにします。(Mac)
- **音声入力。** 入力する代わりに、問題を声に出して話します。(Mac)
- **デスクトップコネクタ。** ローカルのツールやサービスを接続することで、Claudeがあなたのマシン上にあるものを扱えるようにします。

Claudeとエージェント的に働くことは、多くの人にとって新しい働き方です。質問をする代わりに、作業全体をClaudeに渡します — コンテキストを集め、分析を行い、完成品を作り出す — そして完了した状態で戻ってきます。あなたは単に会話しているのではなく、委任しているのです。

**こんなときに使う:**

- **タスクに、通常は順番にこなすいくつかのステップがある。** 数字を取り出し、比較し、要約を下書きし、文書を整形する。任せてしまえば、それは4つの用事ではなく1つの指示になります。
- **出力が、必要な場所に置かれた完成ファイルである。** 一括でリネームされたファイル、正しいフォルダに保存されたスプレッドシート、デスクトップ上の整形済みPDF — これらはあなたが後で整理するために返されるのではなく、ファイルシステムに直接届けられます。(プレゼンテーションや文書単体であれば任せる必要はありません。どの会話でもそれらをアーティファクトとして作成できます — 「アーティファクトで作成する」のレッスンを参照してください。)
- **作業が複数のツールにまたがっている。** 会議メモはある場所に、スレッドはSlackに、前四半期の数字はスプレッドシートに。金曜日のまとめをスケジュールタスクとして設定すれば、実行のたびにClaudeが自分でこの3つすべてを集めてくれます — あなたが先に集めておく必要はありません。
- **スケジュールに沿って、あるいはあなたが他のことをしている間に実行されるべきである。** 金曜日にリリースされたものをレビューする。月曜日に次の会議に備えるブリーフィングを行う。

作業を任せるということは、そこから手を引くことを意味しません。Claudeが作業を始める前に、範囲や形式を明確にするためにいくつか質問することがあり、計画を見せてくれます。作業が進む間、タスクが形になっていく様子 — 参照している情報源、形成されていくファイル、計画の進捗 — を見守り、いつでも方向づけできます。そして、Claudeが行動前に確認するよう設定されている場合、メールの送信やファイルの共有など、重要なアクションについてはあなたの承認を待って停止します。あなたのデスクから出ていくものは、常にあなたがコントロールしています。

**試してみる場面:**

- すべてのツールをデータベースのように問い合わせたいとき。「会議メモ、Slack、メールを横断して、前四半期に価格について決めたことを確認し、その結果でQ3のプレゼンテーションを更新してください」。Claudeはそれらすべてを横断して答えを見つけ、プレゼンテーションを更新します。任せて、作業を続け、結果を確認します。
- 契約書、財務報告書、会議の文字起こしなど、50以上のプロジェクト文書が入ったフォルダがあるとき。あなたの取り組みに最も関連するものを見つけ、要約メモを作成するようClaudeに依頼します。Claudeはすべてのページを読み、すべてを読んだからこそ見えてくるパターンを抽出します。50件を5件のようにレビューできます。
- 毎週月曜日の朝に同じ作業をしているとき — メッセージを確認し、ステータス更新をまとめ、その日の会議の準備をする。一度スケジュールタスクとして設定すれば、事務作業ではなく答えとともに月曜日を始められます。

**現在の製品では。** デスクトップアプリでは、Coworkでタスクを任せることができます。現在提供されている機能は次のとおりです。

- **ローカルフォルダへのアクセス。** Claudeにフォルダを指定すると、そこにあるものを読み取り、完成した作業を同じ場所に保存し直します。これは、アップロードしたものを読み取れるものの、完成ファイルをフォルダに保存するのではなくダウンロードとして返すターンごとのChatとの具体的な違いです。
- **スケジュールタスク。** 毎日のブリーフィング、週次のまとめ、朝の受信トレイの仕分けなど、タスクを一度設定すれば、Claudeが設定した頻度で実行します。スケジュールタスクはリモートで実行されるため、コンピュータがスリープ状態でもアプリが閉じていても実行されます。タスクがコンピュータ上のファイルを使用する場合は、Claudeがアクセスできるようデスクトップアプリを開いたままにしてください。
- **サブエージェント。** 大きな仕事の場合、Claudeはそれぞれ独自のコンテキストを持つバックグラウンドワーカーに並行して作業を分割し、1つの完成した成果物としてあなたに渡します。
- **プロジェクト。** 関連するタスクを、独自のファイル、指示、記憶を持つワークスペースにまとめます — Chatのプロジェクトに似ていますが、実行するタスクを中心に構築されています。
- **ブラウザ使用。** Claude in Chromeを使うと、Claudeはウェブサイトを操作し、見つけたものを直接タスクに取り込みます — 10のサイトにまたがる競合の価格情報、APIのないページからのデータなど。
- **コンピュータ使用。** 必要なもののためのコネクタがない場合、Claudeはコンピュータを直接操作できます — クリック、入力、アプリを開くなど — 触れるアプリごとに許可を求め、立ち入り禁止のものにはブロックリストが適用されます。Pro・Maxプランでリサーチプレビュー中です。
- **プラグイン。** 特定の種類の作業向けに構築された、スキル、コネクタ、エージェントの既製のバンドルです — 営業向けプラグイン、財務向け、法務向けなど — Claudeがその役割の働き方に沿って動作するようにします。Customize → Pluginsから閲覧・追加できます。

Coworkは、Pro、Max、Team、Enterpriseのユーザーが利用でき、新しい機能が定期的に追加されています。

コードを書く場合、デスクトップアプリは完全な開発環境を提供します。Claudeはあなたのコードベース内で直接作業します — そこにあるものを読み、コードを書いて修正し、コマンドを実行します。ビジュアル差分で変更内容がわかり、組み込みのターミナルで実行中のコマンドが表示され、gitがすべてのバージョンを追跡するので、いつでもロールバックできます。開発者でない場合、覚えておくべきことはこれだけです。これは別のタブであり、このコースでは必要ありません — 詳しくは[Claude Code in Action（新しいタブで開きます）](https://academy.claude.com/ja/courses/claude-code-in-action)で扱っています。

作業がどこで行われるかを選べます。

- **ローカル。** コンピュータ上のフォルダを選択すると、Claudeはそれらのファイルを直接操作します — プロジェクトを読み込み、ローカルツールを使用し、ブラウザでプレビューできる開発サーバーを実行します。
- **クラウド。** GitHubリポジトリを接続すると、Claudeはクラウド環境で作業します。アプリを閉じてもセッションは継続するため、大規模なリファクタリングを開始して後で確認することができます。より大きなコードベースに適しており、作業を自分のマシンの外に置いておきたい場合にも向いています。同じ考え方でクラウド上でCoworkを実行することもできます(ProおよびMaxプランで利用可能、Teamプランおよび管理者が有効にしたEnterpriseプランではベータ版) — Introduction to Claude Coworkコースの[Cowork in the cloud（新しいタブで開きます）](https://academy.claude.com/ja/courses/introduction-to-claude-cowork)を参照してください。

Claudeがどこまで自律的に作業するかも選択でき、設定には次のものがあります。

- **手動承認。** Claudeはすべての変更を提案し、あなたの承認を待ちます。
- **編集を自動承認。** Claudeはファイルの編集を自動的に適用します。
- **プラン。** Claudeは変更を加える前に計画を作成します。

**現在の製品では。** これはデスクトップアプリのCodeタブにあり、Pro、Max、Team、Enterpriseプランで利用できます。複数のプロジェクトにまたがって複数のセッションを実行でき、サイドバーから環境(LocalまたはCloud)とステータスでフィルタリングできます。

最初にタブを選ぶわけではありません — 目の前にある作業がどんな種類のものかに気づき、タブはそれに従います。このレッスンの全体を1つの表にまとめました。

| これから行うこと… | 取る形 | 現在の所在 | 
|---|---|---|
| 質問する、ブレインストーミングする、下書きする、あるいはターンごとに何かを考え抜く | Claudeとターンごとにやり取りする | Chat(クイックエントリー、音声入力、スクリーンショット) | 
| 完成した成果物で終わる、複数のツールにまたがる、またはスケジュールで実行される複数ステップのタスクを任せる | 作業を任せる | Cowork(フォルダアクセス、コネクタ、スケジュールタスク、サブエージェント) | 
| コードベースでコードを書き、テストし、実行し、出荷する | ソフトウェアを構築する | Codeタブ(LocalまたはCloud) | 

- 今週Claudeをどのように使ったか考えてみてください。どのリクエストがターンごとの思考で、どれが習慣だからという理由で一度に一つの質問として投げかけていた、実は丸ごとのタスクだったでしょうか?
- 最も手放したいタスクを1つ取り上げてください。それは複数ステップですか、コンピュータ上にファイルを保存して整理する必要がありますか、複数のツールにまたがっていますか? いずれかに当てはまるなら、それは任せるべき作業です — 最初に尋ねる質問ではなく、Claudeに説明する成果を書き出してください。

次のモジュールでは、プロジェクトを使って作業と知識を整理する方法を学びます。
