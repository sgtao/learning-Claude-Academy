## 概要
Claudeの回答が期待と少し違うときの課題5種（一般的すぎる・長さ・フォーマット・誤情報・トーン）と対処法を表で示し、最初のプロンプトは会話の始まりと捉えて改善する姿勢を説く。続けてAI活用力の4Dフレームワーク（委任力・記述力・評価力・倫理的責任）を紹介し、自分のタスクでClaudeの出力を試して評価する手順（サンプル収集→テスト用プロンプト→比較→改善）と、Rioが前四半期データで検証する例を述べる。注意：変換は direct で、動画・画像・リンク先の中身は含まれない。ナビ・フッターなどのページ枠の文言は見当たらない。

## 生成AIの総括
### 期待と違う結果は、改善と検証を重ねる出発点
- 横断分析：
  - 視点1：原因を見つけて指示を足す。表の 5 つの課題は、どれも「起きていること」を見極めて、具体的に伝え直す対処につながる。
  - 視点2：完璧を求めず会話で磨く。最初のプロンプトは会話の始まりで、初稿を出発点に具体的なフィードバックを返す。
  - 視点3：任せてよいかは試して確かめる。評価（eval）やRioの例は、自分が答えを知っているタスクでAIを試し、一致すれば使い、一致しなければ委任しない、という判断の仕方を示す。
  - 視点4：責任は残る。本文は、検証は自信を構築するが責任をなくすものではないと述べ、4Dフレームワークの倫理的責任も、AI支援による作業への説明責任を含むと定義する。
- 一言まとめ：最初の一回で完璧を求めず、具体的に伝え直し、自分の仕事で試して確かめたうえで、任せる範囲を決めて責任は自分が持つ。
