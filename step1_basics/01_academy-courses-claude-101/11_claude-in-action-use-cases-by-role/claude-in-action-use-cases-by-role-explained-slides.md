## 選んで、試して、==見直す==
lead: 本文から読み取れるのは前半の 3 つ。見直しは、このメモの提案
```steps
style: cards
items:
  - icon: "1"
    title: 区分を選ぶ
    desc: 共通・営業・マーケティング・財務・人事・法務・研究者のうち、自分の仕事に近いもの
  - icon: "2"
    title: 例を選ぶ
    desc: 一行説明を読み、いま時間のかかっている作業に近い 1 件を選ぶ
  - icon: "3"
    title: 手順で実践する
    desc: 詳細ガイドのステップバイステップに沿って進める
  - icon: "4"
    title: 見直す【補足】
    desc: かかった時間・手直しの量・次も使いたいかをメモする
    tone: outline
```
point: 1 件を最後までやりきる。1 回で全部を覚えようとしない【補足】
note: 根拠の出典：1〜3 は原本（本文は見出しなし）の「ステップバイステップの手順に沿って実践できます」の段落と区分ごとの導入。解説メモ 02 の「4. ユースケース」（だれが・どうやって）。

## 試す前に、==確認が要る点==
lead: 空白を推測で埋めず、リンク先で確かめる（Why So：本文は題名と一行説明だけだから）
- **手順の中身**：各例のステップは、本文には書かれていない
- **所要の分・必要なプラン／権限**：本文には書かれていない
- **材料**：何を用意して入れるかは、題名と説明から推測するしかない【推測】
- **自分の職種が無いとき**：本文はギャラリーで全コレクションを閲覧するよう案内している。それ以外の探し方は書かれていない
point: 試す前に、使うアカウントで該当の機能が使えるかを確認する【補足】
note: 根拠の出典：解説メモ 02_explanation_memo.md の「注意点・限界」と 11_question_and_answer.md の FAQ（所要時間や必要なプランは書かれていますか／自分の職種が営業や財務などに当てはまらないときはどうしますか）。原本の最後の段落（ギャラリーの案内）。
note: 補足を足した箇所：「材料」の項は解説メモの【推測】、下部の point（アカウントで機能が使えるかの確認）は FAQ の【補足】。所要の分や有料プランの条件は、原本にも解説メモにも書かれていないため、書いていない。

## リンクを開く前に、==3 つ書き出す==
lead: 本文は各例に一行しか説明を付けていない。知りたいことを先に決めておく
- **何を入れるか**：手元のどの材料を使うか
- **結果をどう使うか**：出てきたものを、仕事のどこに使うか
- **どこまで自分で確かめるか**：Claude の出力を、自分でどこまで見直すか
> 試したあとは、書き出した 3 点が詳細ガイドで分かったかを見直す
point: これは本文の指示ではなく、このメモの提案【補足】
note: 根拠の出典：解説メモ 02_explanation_memo.md の「5. 理解を深める質問」の回答（質問 3）と「活用案」（案3：思考プロセスの視点）。原本の「ステップバイステップの手順に沿って実践できます」。
note: 補足を足した箇所：3 つの書き出し項目はすべて解説メモの【補足】であり、原本には書かれていない。

## まとめ：まず==1 件==試す
1. **案内図として読む**：本文は職種別の題名と一行説明のリンク。手順はギャラリーの詳細ガイドにある
2. **区分から選ぶ**：自分の区分、無ければ共通の 3 件から、近い例を 1 つ選ぶ
3. **空白は確かめる**：手順・所要の分・プランの条件は本文に無い。リンク先で確認する
> 次の 1 アクション：自分の仕事で繰り返している作業を 1 つ選び、近い例の詳細ガイドを開く【補足】
note: 根拠の出典：解説メモ README の生成AIの総括（横断分析・一言まとめ）と 02 の活用案。原本の最後の段落（最後のモジュールで、Claude Code など別の協働の方法を紹介する予告）。
note: 補足を足した箇所：次の 1 アクションは解説メモの提案（活用案・一言まとめ）。最後のモジュールで何を扱うかは、原本に製品名の列挙があるだけで、詳しい中身は書かれていない。
