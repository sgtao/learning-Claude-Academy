badge: 1 リサーチ機能とは
## 「答える」から==「調べ上げる」==へ
lead: Claudeを対話型アシスタントから体系的な調査者へ変える機能
- **エージェント的に動く**：次に何を調べるかを判断しながら、積み重なる複数の検索を行う
- **時間がかかる**：質問によって数分かそれ以上。時には数百ものソースを調べる
- **思考モードと連携**：検索を始める前にアプローチを計画する
- **引用で確かめやすい**：確認しやすい引用つきの回答が返る
- **情報源**：ウェブ全体と、接続済みの連携機能
point: 一度の検索ではなく、調査そのものを任せる機能
note: 根拠は原本の冒頭の段落と、4 つの特徴を述べた箇条書きです。原本には見出しがありません。出典は解説メモ 02 の「### 3. セクション別の解説」です。
note: 「数百ものソース」は原本の記述どおりで、ほかの数値は原本にありません。
note: 【補足】解説メモ 02 の「### 2. 例え話」にある筆者の例えです。受付で住所を聞くのが通常の検索、調査担当者に報告書を頼むのがリサーチ機能、というイメージです。原本には無い補足です。

badge: 2 使いどころ
## 向くのは、==何時間もかかる徹底調査==
lead: 通常であれば何時間もの手作業が必要となる調査
- **複数ソースの統合**：包括的なレポート、検証可能な引用つき
- **競合・ベンダーの比較**：選択肢を評価する比較分析
- **市場分析と競合調査**
- **複雑なプロジェクトの計画**：チームの合宿や製品ローンチなど
- **情報の統合・文書化**：メール、カレンダー、ドキュメント、技術文書、ブリーフィングの準備
point: 「複数のソース」と「検証できる引用」が要るなら、リサーチ機能
note: 根拠は原本の「次のような場合にリサーチ機能を使用します」と「リサーチ機能は次のようなタスクに最適です」の 2 つの箇条書きです（原本に見出しはありません）。解説メモ 02 の「### 4. ユースケース」と、11 の FAQ 1・3 に対応します。
note: 本文は例を挙げているだけで、分野ごとの向き不向きの順位は述べていません。

badge: 3 使い分け
## ほかの機能との使い分け
lead: 答えが「どこにあるか」と「速さ」で選ぶ
| 機能 | 向く場面 | 本文の例 |
|---|---|---|
| リサーチ機能 | 複数ソースの統合・徹底調査・比較 | 競合やベンダーの選択肢の評価 |
| ウェブ検索 | 手早い事実、ソースが 1〜2 つ、速さ優先 | 今日の株価、会社の住所 |
| 思考モード | 外部情報のいらない深い推論 | 数学、コードのデバッグ、論理的分析 |
| Enterprise search | 組織内部の知識 | ドキュメント、Slack、メール、会議メモ |
point: 迷ったら「外の情報か、推論か、社内か」を先に決める
note: 根拠は原本の「代わりにウェブ検索を検討すべき場合」「代わりに思考モードをオンにすることを検討すべき場合」「代わりにEnterprise searchを検討すべき場合」の 3 つの箇条書きです。解説メモ 02 の「### 3. セクション別の解説」と、11 の FAQ 3・4 に対応します。
note: 【補足】point の「外の情報か、推論か、社内か」は、解説メモ 05（テーマ：リサーチ機能の使いどころと進め方）の判断の整理を短くした筆者の言い方で、原本にそのままの文はありません。

badge: 4 仕組み
## 起動すると、==4ステップ==で進む
lead: 各ステップを指示しなくても、Claudeが次の一手を自分で判断する
```steps
style: cards
items:
  - icon: "🧭"
    title: 計画する
    desc: 依頼を分解し、必要な情報と調べ方を決める
  - icon: "🔎"
    title: 複数検索する
    desc: 見つけた内容から次を判断し、隙間を埋める
  - icon: "🧩"
    title: 統合する
    desc: ウェブやGmail・Googleカレンダー・Googleドライブの情報を1つのレポートに
  - icon: "🔗"
    title: 引用を付ける
    desc: すべての主張が出典にリンクされる
```
point: 流れは「計画 → 検索 → 統合 → 引用」
note: 根拠は原本の 4 つの番号つきの項目（ステップ 1〜4）で、順序は原本のとおりです。解説メモ 02 の「### 3. セクション別の解説」と、03 の 2 問目の回答に対応します。
note: 「思考モードと連携して動作する」の仕組みの詳細は、原本に書かれていません。

## 有効にする手順は==4つ==
lead: チャット画面から、数クリックで始められる
```steps
style: cards
items:
  - icon: "➕"
    title: +ボタンをクリック
    desc: チャットインターフェースの左下
  - icon: "✅"
    title: リサーチ機能を選ぶ
    desc: メニューから選択。有効になるとハイライト表示
  - icon: "⌨️"
    title: プロンプトを送信
    desc: 入力して送信する
  - icon: "⏳"
    title: 進捗を見て待つ
    desc: バックグラウンドで作業。進捗インジケーターが出る
```
point: 数分かかるので、待つ間は別の作業を進められる
note: 根拠は原本の「リサーチ機能を有効にして使用する方法は次のとおりです。」に続く 4 つの番号つきの手順で、順序は原本のとおりです。解説メモ 11 の FAQ 5 に対応します。

badge: 6 依頼文のコツ
## 分単位の待ち時間だから、==依頼文に時間をかける==
lead: 実行に秒ではなく分がかかる。やり直しの損を減らす
- **目標を具体的に**：「EV市場について教えて」ではなく、電気自動車用バッテリー市場の主要プレーヤー・技術トレンド・サプライチェーンの課題を特定する依頼にする
- **構成を指定する**：例：チーム合宿の会場候補を、立地とアクセス、会議スペースと設備、ケータリング、価格の観点で比較する
- **制約条件を含める**：予算の範囲、スケジュール、地理的な要件
- **Claudeに改善を頼む**：書き方に迷うなら、機能を有効にする前に、より良いプロンプトを書く手伝いを頼む
point: 書くのは「目標・構成・制約」の 3 点
note: 根拠は原本の 4 つの戦略（目標を具体的にする／希望するセクションや構成を指定する／関連する制約条件を含める／Claudeにプロンプトの改善を手伝ってもらう）と、本文中の 2 つの例です。解説メモ 02 の「### 3. セクション別の解説」と、11 の FAQ 6 に対応します。
note: 【補足】point の「目標・構成・制約の 3 点」は、4 戦略のうち依頼文に書く 3 つを選んだ解説メモ 02 の「### 4. ユースケース」の整理で、原本にそのままの文はありません。

badge: 7 連携機能との併用
## 社内の文脈と、ウェブ調査を==1つの依頼==で
lead: メール、カレンダー、ドキュメントの文脈を、ウェブ調査と並行して取得できる
- **依頼例 1**：プロジェクトXについてメールとSlackで話し合われた内容を要約し、類似の取り組みの業界のベストプラクティスを調査する
- **依頼例 2**：来週のカレンダーの予定を確認し、会う予定の各企業について調査する
- **依頼例 3**：価格戦略に関する社内文書をすべて見つけ、競合他社のポジショニングと比較する
- **動かし方**：「Googleドライブから関連するコンテキストを取得して」のように伝えて誘導する
point: 連携を接続しているほど、リサーチ機能は強力になる
note: 根拠は原本の連携機能の段落と、3 つの依頼例（引用符つきの文）です。解説メモ 02 の「### 3. セクション別の解説」と、11 の FAQ 8 に対応します。

## 明日の行動は、==調査 1 件だけ==
lead: 原本の 3 つの問いを、行動の順に並べ直す
1. **洗い出す**：複数のソースから情報を集める調査タスクを書き出す
2. **1 件選ぶ**：調査に時間がかかるため先延ばしにしてきた複雑な質問から選ぶ
3. **依頼文にする**：目標・構成・制約を書く。迷ったらClaudeに改善を頼む
4. **試して確かめる**：数分待ち、引用を開いて重要な数字だけ出典を確かめる【補足】
5. **使う前に**：（要確認: 利用できるプラン・権限の条件。原本には書かれていない）
point: 1 件を依頼文にして 1 回試す。結果を見て、次に足す条件をメモする【補足】
note: 根拠は原本の末尾の 3 つの問いかけ（調査タスク・連携との組み合わせ・先延ばしにした複雑な質問）です。1〜3 はその並べ直しです。
note: 【補足】4 と point の行動案は、解説メモ 02 の「## 活用案」の案 2（学習者の視点）と、03 の 5 問目の回答にある筆者の提案で、原本にはありません。
