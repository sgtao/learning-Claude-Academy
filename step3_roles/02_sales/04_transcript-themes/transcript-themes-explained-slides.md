# 通話記録から、顧客の声を<br>1 枚のテーマブリーフにまとめる
subtitle: Claude Cowork で、件数・最良の一行引用・アカウントつきのテーマを作る手順
badges: [Claude Cowork, 営業, 自己学習]
note: Claude Academy の記事を解説メモにしたものから作ったスライドです。初めて読む人向けに、全体の流れ、フォルダの準備、6 つの工夫、仕組み化の順で進めます。
---
<!-- slide: points -->
badge: 背景
## 通話の山を、==テーマごとの件数と引用==に変える
lead: Sales プラグインの /call-summary が出発点
- **出発点**：ボイス・オブ・カスタマー系のスキルが Sales プラグインに同梱されている
- **できあがるもの**：件数と引用つきの名前付きテーマ
- **プラグインは必須ではない**：管理者が管理していて使えないときは、その手順を飛ばしてよい
- **【補足】** Cowork やプラグインを職場で使えるかは本文に書かれていないので、管理者に確かめます
point: 以降の手順に、プラグインは必須ではない

<!-- slide: steps -->
badge: 全体の流れ
## 準備から共有まで、==6 つの段階==
lead: 一回きりの作業を、少しずつ仕組みにしていく
```steps
style: cards
items:
  - { icon: "🔌", title: 準備, desc: コネクタを設定し、資料を 1 つのフォルダへ }
  - { icon: "💬", title: 依頼, desc: フォルダを指定し、テーマごとの件数・引用・アカウントを求める }
  - { icon: "🧰", title: 工夫, desc: 6 つの指定を足して質を上げる }
  - { icon: "🧩", title: スキル化, desc: 作業を /call-summary に反映する }
  - { icon: "⏰", title: 定期実行, desc: /schedule で新しい四半期のフォルダに自動実行 }
  - { icon: "🤝", title: 共有, desc: スキルを配り、同じテーマ名でそろえる }
```
point: 最初は手で 1 回、慣れてから自動化へ
note: 本文は 1 つの記事で、見出しがありません。この順に段落が並んでいます。どの段階から始めるべきかは本文に書かれていないので、「手で 1 回→スキル化→定期実行」は並びからの整理です。
---
<!-- slide: points -->
badge: 準備
## 資料は、==1 つのフォルダ==にまとめる
lead: Cowork はそのフォルダを、その場で全部読む
- **入れるもの**：トランスクリプトのエクスポート、以前のテーマブリーフ（あれば）、テーマの分類体系（あれば）
- **やること**：そのフォルダを Cowork に指定する
- **書き戻し**：Cowork は、テーマブリーフを同じフォルダに書く
- **四半期ごとに回すなら**：フォルダから Cowork プロジェクトを作ると、分類体系・指示・記憶が保持される
- **コネクタ**：「カスタマイズ → コネクタ」で設定する。権限とアクセスは自分で管理する
point: ソースと出力を同じ場所に置くと、あとで追跡できる
---
<!-- slide: summary -->
badge: 依頼
## 依頼文は、==3 つの要素==でできている
lead: そのまま自分の職場の言葉に置き換えて使える
1. **読む範囲**：フォルダ内のすべてのトランスクリプトを読む
2. **整理のしかた**：顧客の発言をテーマごとにクラスタリングし、各テーマの件数・最良の一行引用・発言したアカウントを示す
3. **出力**：1 ページのテーマブリーフを、プロダクトチームとマーケティングチーム向けにフォルダへ書き出す
> 件数・引用・アカウントの 3 点が、各テーマの根拠になる
point: 「誰に」「何を」「どの長さで」まで依頼に書く
---
<!-- slide: table, compact -->
badge: 6 つの工夫
## 質を上げる指定は、==6 つ==
| 工夫 | ねらい |
|---|---|
| 各発見の根拠を求める | 規模を把握でき、顧客自身の言葉で聞ける |
| 対象読者を指定する | スプレッドシートでなく、行動に移せるブリーフになる |
| 長さの上限を設定する | 1 ページにすると頻度で順位が付く |
| ソースと出力を 1 つのフォルダに | 四半期分を一度に読み、追跡しやすい |
| 手本となる例を追加する | 構成と文体を合わせてくれる |
| 不確実な点の指摘を頼む | 下書きの確認で、どこから見ればよいかがわかる |
---
<!-- slide: steps -->
badge: 仕組みにする
## スキル化から共有まで、==3 つの動き==
lead: 数分の対話で、以降は自分の基準に沿って実行される
```steps
style: cards
items:
  - { icon: "🧩", title: スキルにする, desc: ここまでの作業をスキルにするか、/call-summary を編集する }
  - { icon: "⏰", title: /schedule で自動化, desc: 例：毎週月曜日午前 9 時に、新しい四半期フォルダがあれば前四半期に実行 }
  - { icon: "🤝", title: 共有する, desc: CS・営業が自分の通話に実行でき、プロダクトは同じテーマ名を聞ける }
```
point: テーマは計画の前に届いてこそ役に立つ
note: スキルには、分類体系・セグメント分け・ブリーフの書式が組み込まれます。/schedule の例には、前四半期との違いのセクションも含めるよう書かれています。

## 試す前に、==確かめておきたいこと==
lead: 本文に書かれていない点は、書かれていないと分けて扱う
- **費用・対応プラン・データの扱い**：本文には書かれていない
- **件数と引用の正しさ**：【推測】元のトランスクリプトで人が確かめるのが安全。本文の「不確実な点の指摘」の依頼が助けになる
- **コネクタの「接続」リンク 2 つ**：接続先の説明は本文に無い
