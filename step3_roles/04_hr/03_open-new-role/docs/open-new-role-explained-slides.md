# 新ポジションの職務仕様書を、<br>Coworkの聞き取りで作る

badge: 概要
## この資料でわかること
lead: 採用マネージャーが一人で書くかわりに、Coworkに質問させて仕様書を作る方法
- **聞き取りが先**：インテーク（質問による聞き取り）に答えるだけで、職務仕様書の材料がそろう
- **曖昧さは指摘させる**：あいまいな言葉を、確かめられる形に直してもらう
- **未確定は別リストへ**：決まっていないことは、リクルーター向けの別リストに残す
- **育てて自動化**：作業をスキルにして、平日午前9時に自動で始められる
- **出典**：[Claude Academy「人事：新ポジション開設」](https://academy.claude.com/ja/use-cases/open-new-role)（取得 2026-11-24）
note: 本文の題名は無題です。数値は 90日後 と 平日午前9時 だけで、所要時間や費用の記載は本文にありません。

<!-- slide: points -->
badge: 準備
## 先に、使うファイルを1つのフォルダへ
lead: Coworkはそのフォルダからインテーク中に読み取る
- **フォルダに入れるもの**：職務仕様書テンプレート、レベリングガイド、チーム憲章
- **指定のしかた**：フォルダをCoworkに指定する。完成した仕様書も、そこに書き戻される
- **定期的に開くなら**：親のHiringフォルダからCoworkプロジェクトを作る。テンプレートと指示が紐づいたままになる
- **外部との接続**：Customize → Connectors で設定。権限とアクセスは自分で管理する
- **前提**：Human Resourcesプラグインの /recruiting-pipeline が出発点。管理者が管理していて未提供なら、この手順は飛ばしてよい
point: プラグインが使えない場合は、この手順を飛ばしてよい
note: 「以下の内容はこれを必須としません」の「これ」はプラグインを指すと読んだ推測です。

badge: 全体の流れ
## 手順は、==6つの段階==
lead: 準備 → 依頼 → 確認 → スキル化 → 自動化 → 共有
```steps
style: cards
items:
  - icon: "📁"
    title: 準備
    desc: テンプレート類を1つのフォルダに入れ、Coworkに指定する
  - icon: "💬"
    title: 依頼
    desc: インテーク、曖昧さの指摘、仕様書作成、未解決リストを頼む
  - icon: "🔍"
    title: 確認
    desc: 確信が持てない部分のフラグから見る
  - icon: "🧩"
    title: スキル化
    desc: 作業をスキルにする。または /recruiting-pipeline を編集させる
  - icon: "⏰"
    title: 自動化
    desc: /schedule で、新しいフォルダが現れたら始める
  - icon: "🤝"
    title: 共有
    desc: すべての採用マネージャーで同じスキルを使う
```
note: 確認の段階は、本文の「確信が持てない部分にフラグを立ててください」から、解説メモがまとめた順序です。

badge: 依頼文
## 依頼文は、==4つの柱==
lead: 本文の依頼文を、役割ごとに分けて読む
- **聞く項目**：この人が担当する業務／必須スキルと歓迎スキルの違い／レベルとレポートライン／90日後に良いとされる状態
- **曖昧さの指摘**：「私が曖昧な場合は指摘してください」。あいまいな言葉を、検証できる指標に変える必要に気づかせる
- **仕様書の作成**：当社の標準フォーマットで職務仕様書を作る
- **未解決事項**：リクルーターにまだ未解決の事項をリストアップさせる
point: 会話そのものが成果物になるので、仕様書は職種名ではなく自分の回答から作られる
---
<!-- slide: table -->
badge: 工夫
## 依頼を強くする、==6つの工夫==
| 工夫 | 本文のねらい |
|---|---|
| 作成前にインタビューしてもらう | 仕様書を職種名の推測ではなく、回答から作る |
| 指摘する許可を与える | あいまいな言葉を検証できる指標にする |
| 未解決の質問を別にリストアップ | 報酬レンジや勤務地の柔軟性を仕様書から外す |
| テンプレートを作業フォルダに置く | 標準フォーマットとレベルの定義が、全員で同じ意味になる |
| 参考にする例を追加する | 構成とトーンを、気に入った例に合わせる |
| 不確実な点を指摘してもらう | ドラフト確認で、最初に見る場所が分かる |
note: 本文は6つの工夫を太字の見出しで挙げています。表の右列は、各見出しの下の説明を短くしたものです。

badge: 自動化
## 新しいフォルダが現れたら、==自動で始まる==
lead: プロンプトに /schedule と入力するか、サイドバーのScheduledを開く
```steps
style: circled
items:
  - { icon: "📂", title: Hiringに新しいフォルダ }
  - { icon: "🤖", title: カスタマイズ済みスキルが会話を開始 }
  - { icon: "💬", title: インテークを実施 }
  - { icon: "💾", title: 記録と職務仕様書を保存 }
```
point: 本文の例は、平日午前9時に新しいサブフォルダを確認して実行する指示
note: 例の指示文は、本文では「平日午前9時に、Hiring内の新しいサブフォルダを確認し、それぞれで /recruiting-pipeline を実行し、インテークの記録と完成した職務仕様書をそこに保存してください」です。

badge: 注意
## つまずきやすい点と、==書かれていないこと==
lead: 自分の仕事に使う前に確認する
- **プラグインが未提供**：本文は、その場合はこの手順を飛ばすよう書いている
- **接続のリンク名**：本文では「接続」としか書かれていない。リンク先URLからは Google Drive・Slack・Microsoft 365 向けと読める（推測）
- **本文に書かれていないこと**：所要時間、費用、自動実行が失敗したときの扱い、仕様書の品質の確かめ方
- **自動化の順序**：本文は、手動で会話 → スキル化 → スケジュール、の順に書いている。基準が固まってから自動にするのが安全（解説メモの補足）
point: 本文にない点は、自分のチームで試して確かめる

<!-- slide: summary -->
## まとめ
1. **聞き取りが先**：先に質問に答えれば、仕様書は自分の回答から作られる
2. **曖昧さと未確定を分ける**：曖昧な言葉は指摘させ、未確定の項目は別リストへ回す
3. **フォルダで基準をそろえる**：テンプレート、レベリングガイド、チーム憲章を1つのフォルダに置く
4. **手動 → スキル → 自動**：数分間の会話で、以降は自分の基準で実行されるようになる
