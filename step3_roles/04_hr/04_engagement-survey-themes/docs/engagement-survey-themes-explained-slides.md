# サーベイの声を、==30日で動く計画==にする

## 作業は、==5つの動き==
lead: 本文の記述を順番に並べ直した整理（筆者の補足）
```steps
style: cards
items:
  - icon: "📁"
    title: フォルダに集める
    desc: 調査CSV・組織名簿・前回のブリーフを1つのフォルダへ
  - icon: "💬"
    title: 依頼する
    desc: テーマ化・セグメント化・少数意見の分離を頼む
  - icon: "🔒"
    title: ルールを書く
    desc: 引用を個人に紐付けない。回答者の数で重み付け
  - icon: "🔍"
    title: 草案を確認する
    desc: 確信が持てない部分のフラグから見る
  - icon: "🔁"
    title: スキルにして回す
    desc: /schedule で定期実行し、形式を共有
```
point: 順番は本文の記述を並べ直したもの。本文自体が番号を振っているわけではない
note: 5つの動きは、フォルダの段落、依頼の段落、6つの工夫、スキル化と定期実行の段落を順に並べ直した筆者の整理です。

## 準備：出発点と、使うファイル
lead: Coworkはそのフォルダから読み、結果もそこへ書き戻す
- **出発点**：Human Resourcesプラグインの /org-planning があれば使える。管理者が管理していて使えない場合は読み飛ばせて、以降の内容はプラグインを必要としない
- **入れるもの**：生の調査CSV、セグメント化用の組織名簿、前回サイクルのブリーフ
- **やること**：マシン上の1つのフォルダにドラッグし、Coworkをそこに向ける
- **書き戻し**：Coworkが Peopleブリーフとアクションプランをそのフォルダへ書く
- **四半期ごとの調査なら**：親のエンゲージメントフォルダからCoworkプロジェクトを作ると、過去のサイクルと匿名化ルールが紐付いたままになる
- **連携**：Coworkは連携先の権限とアクセスを自分で管理できる。本文にはSlackとGoogle Driveの接続リンクが並ぶ
note: 本文には、Customize から Connectors に移動して設定するとあります。画面操作の細かい手順は本文に書かれていません。

<!-- slide: points -->
## 依頼：何を頼み、何を受け取るか
lead: 声高な少数意見と、広範なシグナルを分ける
- **頼むこと**：自由記述の調査回答をテーマ化し、データが許す範囲でチームと在籍期間でセグメント化する
- **分けること**：声高な少数意見のコメントと広範なシグナルを分離する
- **受け取るもの**：トップ3つのテーマ、テーマごとに2〜3件の裏付けとなる引用、それぞれの30日間のアクションプランの草案
- **守ること**：引用を個人に紐付けない
point: テーマごとにアクションまで頼むと、報告書でなくリーダーが会議でコミットできる読み物になる
note: 重みは、何人の異なる回答者がそのテーマを挙げたかで付けます。少数の人が強く書いたかどうかでは決めません。

## 精度を上げる6つの工夫
lead: 依頼文とフォルダの両方で、ルールと文脈を渡す
| 工夫 | 本文の指示 | 期待される効果 |
|---|---|---|
| プライバシー | 引用を個人に紐付けない（常設指示） | 名前・役職・小規模チームの識別子が取り除かれ、経営層と安全に共有できる |
| 重み付け | 異なる回答者の数でテーマを重み付け | 強く書く少数と、広い声を区別できる |
| テーマごとのアクション | 30日間のアクションプランの草案を求める | 会議でコミットできる読み物になる |
| 文脈の提供 | 生のエクスポートと名簿を作業フォルダに置く | 実際の組織構造で分類でき、元データの隣に保存される |
| 参考例 | 気に入った例をフォルダに入れる | 構成と文体が例に合う |
| 不確実点のフラグ | 確信が持てない部分にフラグを立てさせる | 草案の確認で最初に見る箇所が分かる |
note: 6つは本文の太字の見出しの数です。表の右列は本文の説明を短くまとめたものです。

## 運用：スキルにして、定期的に回す
lead: 同じ形式のブリーフを、誰が作っても出せるようにする
- **スキル化**：これまでの作業をスキルにする。または、自分のフィードバックで /org-planning スキルを編集する
- **定期実行**：調査は四半期ごとに同じペースで締め切られる。/schedule の例は、毎週月曜日午前9時に新しいエクスポートへ実行する指示
- **共有**：匿名化ルール、セグメントのしきい値、アクションプランの形式が組み込まれたスキルを共有する
- **調査ツール**：Lattice、CultureAmp、Googleフォームのいずれで実施されても、リーダーは一貫した報告を見られる
point: 匿名化ルールと形式を共有すれば、HRBPが同じ形式のブリーフを作れる
note: /schedule の例は、People/engagement の四半期フォルダに新しいエクスポートがあれば、実行してブリーフとアクションプランをそのフォルダに書く、という内容です。

## つまずく所と、本文に無いこと
lead: 使う前に確かめておきたい点
- **本文には書かれていない**：調査CSVの列の作り方、しきい値の具体的な数値、アクションプランの書式の見本、画面操作の詳細、費用やプラン
- **推測（本文から決められない）**：小規模チームの識別子を取り除くのは、人数が少ないと回答者が特定されやすいため、と読める。何人以下が小規模かは分からない
- **推測**：「データが許す範囲で」とあるため、在籍期間などの情報が無い調査ではセグメント化が粗くなると読める
- **補足**：草案はAIの出力。フラグの付いていない箇所も含めて、人が元の回答と照らして確かめる
note: 推測と補足は、解説メモの注意点と同じ印の付け方にそろえています。事実として扱わないでください。

## まとめ：4点で持ち帰る
1. **集める**：調査CSV・組織名簿・前回のブリーフを1つのフォルダへ
2. **守る**：引用を個人に紐付けず、回答者の数で重みを付ける
3. **動ける形にする**：トップ3つのテーマに、30日間のアクションプランの草案を付ける
4. **仕組みにする**：スキル化し、/schedule で定期実行し、形式を共有する
> 自分の職場で試すなら、まず3種類のファイルのうち、手元にあるものを確かめるところから始める。
