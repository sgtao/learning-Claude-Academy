# アドホックなデータ質問に<br>Claude で答える
subtitle: 質問と資料を整え、Skill にして、下書きの自動化と共有までつなげる

## この資料が扱うこと
lead: ビジネス側から届く「なぜ数値が動いたのか」に、Claude で答える手順
- **場面**：「今四半期、EMEA の粗利益率が下がっているのはなぜか」のような、不定期に届く質問に答える。
- **流れ**：資料を1つのフォルダにまとめ、質問をそのまま貼り、SQL と回答メモを書かせる。
- **仕上げ**：やったことを /adhoc-answer という Skill にして、下書きを毎時つくる自動化と共有につなげる。
- **準備**：Data プラグインは出発点になるが、無くてもプロンプトは動く。
point: 狙いは、誰に聞いても ==同じ数値== で答えが返る状態をつくること
note: 全体の根拠は解説メモの概要と各セクションの解説です。Data プラグインの有無は必須条件ではありません。

## 接続と、資料のフォルダ
lead: Claude が実際のテーブル名に沿って SQL を書けるようにする
- **接続**：コネクタで、Claude に使わせたいツールをつなぐ。権限とアクセスは自分で管理する。
- **フォルダに入れるもの**：スキーマのエクスポート、dbt モデル、メトリクスライブラリ、データディクショナリ。
- **書き戻し**：Claude はフォルダから読み取り、SQL・結果のテーブル・回答メモをそこに書き戻す。
- **プロジェクト化**：質問が定期的に来るなら、そのフォルダからプロジェクトを作ると、命名規則と認定メトリクスのリストが引き継がれる。
point: 資料を渡すと、SQL は架空のものではなく ==実際のテーブルとメトリクス名== に対して書かれる
note: 本文には、コネクタの接続手順の細部と権限の設定の詳細は書かれていません。

## サンプルの質問は 3 つを頼んでいる
lead: 質問は言い換えずに、そのまま貼る
- **(a) SQL**：質問に答える SQL を書き、データウェアハウスで実行する。
- **(b) 要因**：何がこの変動を引き起こしているのかを説明する（どのセグメントか、どの変化か、どの日付か）。
- **(c) チャート仕様**：誰も二度と尋ねなくて済むよう、ダッシュボードに追加するチャート仕様を渡す。
> (a)〜(c) の区切りは、読みやすくするための整理です。
point: 質問を ==そのまま== 使うと、回答が相手の質問と相手の言葉に沿ったものになる
note: サンプルの質問は「今四半期、EMEA の粗利益率が下がっているのはなぜですか?」です。

<!-- slide: table -->
## 頼み方のコツ 6 つ
| コツ | 得られること |
|---|---|
| 質問をそのまま貼る | 相手の言葉に沿った回答になる |
| 数値を動かした要因を尋ねる | セグメント・変化・日付の内訳が出る |
| 再利用できる成果物を求める | 次回は質問者自身が更新できる |
| フォルダにコンテキストを置く | 実際のテーブル名とメトリクス名で SQL が書かれる |
| 気に入っている例を入れる | 構成とトーンを例に合わせてくれる |
| 不確かな点にフラグを頼む | 下書きで、まず確認すべき場所が分かる |
point: フラグがあれば、下書き全体を同じ強さで疑わず、不確かな点から見直せる
note: 最後の行の効果の補足は解説メモの補足です。Claude 自身の自信の表明が正しいかどうかは、本文に書かれていません。

## Skill 化、自動化、共有の ==3 ステップ==
lead: うまくいった作業を、人手を介さず回る形にする
```steps
style: cards
items:
  - icon: "📝"
    title: Skill にする
    desc: "ここまでの作業を /adhoc-answer という Skill にして保存。保存されていなければ頼む"
  - icon: "⏰"
    title: 下書きを自動で用意
    desc: "平日は毎時、Teams の #analytics-requests を確認し、送り返す前にレビューできる下書きを書く"
  - icon: "🤝"
    title: 全員で共有
    desc: ウェアハウスのモデル、認定メトリクス、回答フォーマットを同じ定義で使う
```
point: 自動化は下書きまで。送り返す前の ==レビューは人が行う==
note: 下書きまでにして人が見る理由は本文に明記されていません。人が見ないまま送ると誤りがそのまま伝わるため、というのは解説メモの推測です。

## 試す前の注意点
lead: 前提と、資料に書かれていないこと
- **PC の条件**：スケジュール済みタスクの実行中は、デスクトップアプリを開いたまま PC をスリープさせない。
- **プラグイン**：管理者が管理していて使えないときは、そのステップを飛ばす。
- **書かれていないこと**：コネクタ接続の細部、権限の範囲、実行結果の正しさを確かめる方法。
- **推測**：確認の担当者や時間を決めておかないと下書きが溜まる可能性や、資料が古いと古い定義の回答になる可能性がある。
point: 職場で外部ツールへの接続が制限されている場合は、先に管理者へ確認する
note: 「推測」と書いた項目は、解説メモの推測です。資料本文には書かれていません。

## まとめ
1. 質問は言い換えずに貼り、資料は ==1 つのフォルダ== にまとめる。
2. SQL・回答メモに加え、チャート仕様まで求めて、次回は質問者が更新できるようにする。
3. 作業を /adhoc-answer という Skill にし、毎時の下書きと共有につなげる。
4. 最初の一歩：自分の職場で、フォルダに入れられる資料（スキーマ、メトリクスの定義など）を洗い出す。
point: 質問と資料を整えて Skill にすれば、誰に聞いても同じ数値で答えられる
note: 4 は解説メモの確認の質問に基づく、読み手向けの次の一歩です。
