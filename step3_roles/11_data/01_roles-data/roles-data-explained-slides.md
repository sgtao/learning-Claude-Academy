## ==六つ==のプロンプトが並んでいる
lead: どれも下書きとして開かれ、送信前に編集できる

| プロンプト | 本文の説明 |
|---|---|
| クエリを作成 | データに関する重要な問いに答える SQL を作成する |
| データパイプラインをデバッグ | 失敗や遅延が出ているパイプラインの、考えられる原因を特定する |
| A/B テストのレポートを作成 | 結果と推奨事項を含むサマリーを作成する |
| ダッシュボードを作成 | エクスポートしたデータから、実際に使えるダッシュボードを作る |
| 週次の指標レポートを作成する | エクスポートしたデータや接続済みのソースから、週次の指標をまとめる |
| データファイルのクレンジング | 既存のデータファイルを整え、加えたすべての変更をログに記録する |

point: 問いに答える、不具合を調べる、報告する、データを整える。データ業務の一通りの場面が並ぶ
note: 本文は一覧だけで、各プロンプトの中身は書かれていません。非エンジニアは、報告に近いダッシュボードや週次の指標レポートから試すのが現実的、というのは解説メモの補足です。

## 使うときの流れは、==4ステップ==
lead: 本文が書くのは「下書きとして開かれ、送信前に編集できる」まで。流れは解説メモの整理

## 学ぶ前に知っておくこと
lead: 本文に書かれていないこと、読み方の目安
- **事例は二つ**：ユースケース「Answer the ad-hoc data question」（10分）と、チュートリアル「Using Databricks for Data Analysis」（13分）。題名は英語
- **書かれていないこと**：各事例の手順、必要な準備、結果の品質。実際に開いて確かめる必要がある
- **読む順番**：短いユースケースから入るのが負担の少ない順（解説メモの推測）。Databricks を使わない人は、環境が合うかを先に確かめる
- **クレンジングの注意**：変更はログに残るが、元のファイルが上書きされるかは書かれていない。試す前に元のファイルを別に保管する
- **出典**：[データの役割ページ（Claude Academy）](https://claude.ai/learning/roles/data)、取得日 2026-11-24
point: ページは入口。==一つ選んで試し==、結果を自分の言葉で書き留める
note: 時間の意味と読む順番は推測です。確かめるには、事例のページを実際に開く必要があります。
