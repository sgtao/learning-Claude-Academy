# オンコール引き継ぎを<br>Cowork に書かせる
subtitle: 見る場所・書く欄・出す先を決めて、毎週自動で届ける
badges: [技術・ハウツー, Claude Cowork, 初めて読む人向け]
note: 出典は解説メモ（README・解説メモ・FAQ）。原本は Claude Academy の使用例ページ。
---
<!-- slide: points -->
badge: 背景
## 引き継ぎは、==毎回同じ形==で届けたい
lead: 次の担当者が手探りでシフトを始めないための仕組み
- **オンコール**：【補足】緊急の障害に備えて、交代で待機する当番のこと
- **引き継ぎブリーフ**：次の担当者に状況を渡すまとめ。ステータス・一行の原因・注意点を載せる
- **Cowork に任せる**：システムと直接つなぎ、フォルダのテンプレートを読んでブリーフを書き戻させる
- **出発点**：Engineering プラグインの /standup。使えない場合でも、以降の手順はプラグインを必要としない
point: 前の担当者が疲れて書けなくても、誰も手探りでシフトを始めずに済む
note: 本文は「前の担当者が疲れすぎて書けなかったために誰もシフトを手探りで始めることがなくなる」と述べている。

## 準備は、==接続・フォルダ・プロジェクト==
lead: 依頼の前にそろえておくもの
```steps
style: cards
items:
  - icon: "🔌"
    title: 接続を設定
    desc: Customize → Connectors で設定。権限とアクセスは自分で管理する
  - icon: "📁"
    title: フォルダにまとめる
    desc: 引き継ぎテンプレート・先週のブリーフ・ランブックインデックスを1つのフォルダへ
  - icon: "🗂️"
    title: プロジェクトにする
    desc: オンコールフォルダから作ると、テンプレート・チャンネルリスト・重大度の定義が保持される
```
point: Cowork はフォルダからテンプレートを読み、ブリーフとウォッチリストをそこへ書き戻す

badge: 依頼文
## 依頼文で決めるのは、==場所・欄・出す先==
lead: 見る場所・書く欄・出す先を名指しする
| 決めること | 本文の例 |
|---|---|
| 見る場所 | 過去7日間のページとインシデントチャンネル／#support-escalations の CS エスカレーション／本番デプロイ |
| 書く欄 | ステータス（解決済み・監視中・未解決）／判明している場合は一行の原因／次の担当者が注意すべき点 |
| 出す先 | オンコールフォルダへ書き込み、#oncall に投稿 |
note: 本文の依頼文は「私のシフトのオンコール引き継ぎを書いてください」から始まる。保存先と投稿先は、自分のチームのものに置き換える。
---
<!-- slide: table, layout: compact -->
badge: コツ
## 依頼文に==足す指定==で、質が決まる
lead: 本文が挙げるコツと、そのねらい
| コツ | ねらい |
|---|---|
| 必要なソースをすべて指定 | ページ・CS エスカレーション・デプロイは次の担当者を起こす3つの要因。全部で漏れを防ぐ |
| 各項目の欄を指定 | その組み合わせが午前2時のトリアージに必要なもの |
| 出力先を指定 | 記録はフォルダに、目に触れるのは #oncall に |
| 前回版を含める | 前回「監視中」としたものが、削除されずに引き継がれる |
| ノイズの多いアラートを尋ねる | 3回以上発生したアラートを一覧にし、調整のバックログにする |
| ランブックのリンクを頼む | 未解決のものの修正方法へ、ワンクリックで行ける |
note: ランブックは障害時の対応手順書のこと（補足）。

badge: 定着
## 一度うまくいったら、==スキル化して自動化==
lead: 引き継ぎは毎週同じ時間に発生するので、仕組みに任せる
```steps
style: circled
items:
  - icon: "🧩"
    title: スキルにする
    desc: これまでの作業をスキルにするか、フィードバックで /standup を編集する
  - icon: "⏰"
    title: 定期実行にする
    desc: /schedule か Cowork の Scheduled で設定。例は毎週月曜日午前9時
  - icon: "👥"
    title: 共有する
    desc: チャンネルリスト・ステータスラベル・テンプレート入りのスキルを全員で使う
```
point: 覚えていたかどうかに関わらず、ローテーションの終わりごとにブリーフが作られる
note: 例の保存先は Platform/Oncall/ の週ごとのファイル。時刻と保存先はチームに合わせて決める（補足）。

## 本文から==分からないこと==もある
lead: 推測や補足は印を付けて区別する
- **「ページ」の意味**：本文に定義はない。【推測】緊急の呼び出し通知を指す
- **接続先の名前**：リンクの文字は「接続」だけ。URL から PagerDuty・Slack・GitHub と読める【推測】
- **出来上がりの例**：本文にブリーフの実例はない。内容は人が確かめる【補足】
- **管理者の設定**：プラグインや接続が管理下にあるとき、自分でどこまで設定できるかは書かれていない
- **詳しく読む**：[原本ページ](https://academy.claude.com/ja/use-cases/oncall-handoff-brief)・[解説メモ](./oncall-handoff-brief_explained/02_explanation_memo.md)・[FAQ](./oncall-handoff-brief_explained/11_question_and_answer.md)

<!-- slide: summary -->
## まとめ：==決めて、渡して、任せる==
1. 見る場所・書く欄・出す先を、依頼文で名指しする
2. 前回版を渡して、「監視中」を引き継ぐ
3. 一文足して、アラートの整理とランブックへの入口にする
4. スキル化して /schedule で毎週自動に、共有して全員が同じ形で書く
