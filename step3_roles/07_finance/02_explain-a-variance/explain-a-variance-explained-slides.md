# Claude Cowork で==差異コメンタリー==を作る
subtitle: 月次レビューの説明文を、基準と読み手を伝えて作り、運用に乗せる
badges: [財務, Cowork, 初めて読む人向け]
note: Claude Academy のページ「差異を説明」の解説メモ（README・解説メモ・FAQ）だけを元にしたデッキです。Web 検索はしていません。

badge: 全体像
## この資料で分かること
lead: Finance プラグインの /variance-analysis を使う、月次の差異の説明づくり
- **何をするか**：実績を前月および予算と比べ、大きく変動した行を、何が・なぜ変動したか、経営層向けに説明させる
- **何が要点か**：しきい値・読み手・出力先・参考例・不確実な点の指摘、という 5 つの指定
- **その先**：作業をスキルにし、公開・定期実行・共有で毎月のクローズに組み込む
- **前提**：プラグインが管理者管理で使えない場合は、この手順をスキップしてよい。以降の内容はプラグインを必要としない
note: 「この手順をスキップ」の範囲は本文から断定できないため、解説メモでは推測として扱っています。

lead: 材料を渡す → 依頼する → 指定で磨く → 運用に広げる

point: まず 1 回作らせてから、指定を足して磨く

## 材料と基本のプロンプト
lead: 本文の例をそのまま最初の試行に使える
- **材料**：実績、前期、予算、勘定科目表を、マシン上の 1 つのフォルダに入れ、Cowork にそのフォルダを指定する
- **読み書き**：Cowork はそこから読み取り、ナラティブ（差異の説明文）をそこに書き戻す
- **依頼の骨子**：実績を前月および予算と比較し、==10%または5万ドル==を超えて変動した行を、経営層向けに説明する
- **毎月使うなら**：そのフォルダから Cowork プロジェクトを作ると、指示・メモリ・スケジュール実行がフォルダに紐づく
- **外部サービス**：「カスタマイズ → コネクタ」から接続する。接続先は URL から Google ドライブと Microsoft 365 と読める（推測）
note: 10% と 5万ドルは本文の例の値です。自分の組織の基準に置き換える必要があります（補足）。

badge: 5つの指定
## プロンプトに足す==5つの指定==
lead: 何を省き、誰に向けて、どの形で書くかを先に決める
| 指定 | 内容 | 効果 |
|---|---|---|
| しきい値を設定する | 10%または5万ドルを重要性の基準線にする | 重要な事項をカバーし、それ以外は省略する |
| 読み手を明示する | 「経営層向けに」と伝える | 監査版より行レベルの詳細が少なく、解釈が多くなる |
| 出力先を指定する | 特定のファイルを指定する | そのファイルを編集。指定なしは作業フォルダ内にドラフト |
| 参考例を追加する | 前四半期のコメンタリーをフォルダに入れる | 構成や文体に合わせる |
| 不確実な点を指摘させる | 要因が明確でない行にフラグを立てさせる | レビュー前に深掘りすべき行が分かる |
point: 5 つとも、依頼文に 1 行足すだけで試せる

## つまずきやすい所と、書かれていないこと
lead: 本文の範囲と、補足・推測を分けて確認する
- **しきい値の単位**：本文の例はドル。通貨や規模が違う組織では、数字の置き換えが要る（補足）
- **要因が不明な行**：フラグを付けさせたら、人が元の資料で確かめる（補足）
- **「または」の読み方**：割合か金額のどちらか一方を超えれば対象、と読める（推測）
- **本文に無いこと**：出力例の文面、費用・プラン・権限、他 7 つのスキル名、共有の具体的な操作
note: 「補足」「推測」は解説メモの印です。本文に書かれている内容とは区別して読んでください。

## 1回で終わらせず、==4つの手順==で仕組みにする
lead: スキル化 → 公開 → 定期実行 → 共有
```steps
style: cards
items:
  - icon: "🧩"
    title: スキル化
    desc: "プラグインのスキルは出発点。数分の対話で自分の基準に合わせる"
  - icon: "🔗"
    title: 公開
    desc: "コネクタ経由で実績を読むアーティファクトにし、開くたびに最新の数字を表示"
  - icon: "⏰"
    title: 定期実行
    desc: "/schedule かサイドバーの「スケジュール」で自動実行"
  - icon: "👥"
    title: 共有
    desc: "同じバージョン・しきい値・フォーマット・文体で全員が実行"
```
point: ドキュメントはスナップショット。最新を見せるなら公開を使う
note: 定期実行の本文の例は、毎週月曜午前9時に、FY26-Close に新しい実績ファイルがあれば実行してドラフトを書き込む、というものです。

## まとめ
1. **基準と読み手を先に伝える**：しきい値・読み手・出力先・参考例・不確実な点の指摘の 5 つ
2. **フォルダに材料を置く**：結果もそこに書き戻させる形が、運用の土台になる
3. **人の確認は残す**：要因が明確でない行は、フラグを頼りに人が深掘りする（推測）
4. **うまくいった作業は仕組みに**：スキル化・公開・定期実行・共有で毎月のクローズに再利用する
note: 一言まとめ：Claude には基準・読み手・出力先を先に伝え、うまくいったやり方はスキルにして毎月のクローズで再利用する。
