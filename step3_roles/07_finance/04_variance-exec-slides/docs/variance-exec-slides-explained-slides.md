# 差異分析から、<br>==経営層向けの3枚==を作る

## この記事は、==一度の依頼を毎回使える仕組み==に育てる話
lead: 月次の差異分析ワークブックから、3枚の .pptx を作る手順
- **何を作るか**：実績対計画のヘッドライン、主要な変動要因と一時的要因を示すドライバー、Q2 への持ち越しを示す見通し、の3枚
- **どう作るか**：資料を1つのフォルダに集めて Cowork に指定し、そこから読み取らせて .pptx を書き戻させる
- **どこまで進むか**：頼み方のコツ6つ、スキル化、/schedule での毎週の自動実行、共有まで
- **差異とは**：実績と計画のずれのこと（解説メモの用語補足）
point: ゴールは「毎四半期の取締役会準備が、同じ形で再現できる」こと
note: 差異分析は、実績と計画のずれを調べる作業です。これを経営層向けに3枚へ絞るのがこの記事の主題です。
note: 一言まとめ（解説メモ）：3枚を名指しで頼み、実例と基準を渡し、スキルにして /schedule で回す。

## 準備から自動化まで、==6つの段階==
lead: 一度に全部やらず、上から順に進める
```steps
style: cards
items:
  - icon: "📁"
    title: 準備
    desc: 差異のワークブックなど3種の資料を1フォルダに
  - icon: "🧱"
    title: 土台
    desc: board-prep フォルダから Cowork プロジェクトを作る
  - icon: "✍️"
    title: 依頼
    desc: 3枚の名前と役割、出力先を1つの依頼文に書く
  - icon: "🔧"
    title: 調整
    desc: 6つのコツで、出力を整える
  - icon: "📦"
    title: 定着
    desc: 作業内容をスキルにする
  - icon: "⏰"
    title: 自動化
    desc: /schedule で毎週月曜の午前9時に実行
    tone: outline
```
point: 手作業で固めてから、スキル、定期実行の順に進める
note: 解説メモの「詳細解説」の表（準備・土台・依頼・調整・定着・自動化・共有）を、共有を除いて6段階にまとめました。共有は後のスライドで扱います。

## 頼むのは、==この3枚だけ==
lead: 名前と役割を依頼文に書くと、余計な4枚目を防げる
```steps
style: cards
items:
  - icon: "📊"
    title: ① ヘッドライン
    desc: 実績対計画を示す
  - icon: "🧭"
    title: ② ドライバー
    desc: 主要な変動要因と、既知の一時的要因を示す
  - icon: "🔭"
    title: ③ 見通し
    desc: Q2 に持ち越される内容を示す
    tone: outline
```
point: ヘッドライン／ドライバー／見通しは、CFO が期待する構成
note: 根拠は解説メモの引用「それを明示的に述べることで、余計な4枚目のスライドが生まれることを防げます」です。
note: 解説メモの推測：3月と Q2 の組み合わせは、会計年度の定義によって読み替えが必要になります。

## 資料は==1つのフォルダ==に集め、プロジェクトにする
lead: 毎回言い直さなくて済む土台を先につくる
- **集める資料**：差異分析ワークブック、前四半期のデッキ、既知の一時的要因のリスト
- **指定のしかた**：フォルダを Cowork に指定する。Cowork はそこから読み取り、.pptx をそこに書き戻す
- **プロジェクト化**：board-prep フォルダから Cowork プロジェクトを作ると、重要性の閾値・スライドテンプレート・CFO が好む表現が維持される
- **コネクタ**：Microsoft 365 や Google Drive を使うときは、Customize → Connectors で接続する
point: 繰り返し使う値は、プロジェクトの指示に1か所だけ書く
note: 重要性の閾値は「これ以上の差異だけを取り上げる」という基準の金額や割合です。具体的な値は記事に書かれていないので、自分の値を入れます。
note: 解説メモの推測：board-prep、close、FY26-Close/Board-prep は同じ作業フォルダ群の呼び方と思われますが、断定できません。

## 頼み方の==6つのコツ==
lead: どれも「先に決めて、言葉にする」ことが共通している
- **名前を付ける**：出力の各部分に名前を付ける
- **疑問を予測する**：経営層が最初に尋ねる質問を先回りする。例はドライバーページで一時的な項目を分けること
- **実例を示す**：前四半期のデッキそのものを渡す。説明よりも実例のほうが合わせやすい
- **値を保存する**：繰り返し使う値はプロジェクトの指示に保存する
- **チャートを指定する**：ドライバーページにウォーターフォールチャートを使う、など
- **ノートを頼む**：補足の詳細はスピーカーノートに入れ、ページはすっきりさせる
point: 実例と基準を渡すほど、出力が安定する
note: ウォーターフォールチャートは、増減を階段状に積み上げて、合計までの変化の内訳を示すグラフです。差異の説明に向きます（解説メモの補足）。
note: 自分の業務で経営層が最初に尋ねる質問は、記事には書かれていません。過去の会議の議事録などから拾って決めます。

## スキルにして、==毎週月曜の午前9時==に回す
lead: 一度の対話の成果を、次回からの標準にする
- **スキル化**：このタスクでこれまで行ったことをスキルにするよう頼む。または、フィードバックで /financial-statements スキルを編集する
- **出発点として**：プラグインのスキルは出発点。自分のやり方でカスタマイズする
- **定期実行**：/schedule、または Cowork のサイドバーの Scheduled から。新しいワークブックがあれば3枚を作り、.pptx をフォルダに書き出す
- **共有**：スキルには3枚構成・重要性の基準・CFO が好むフレーミングが入る。共有すると、各事業部門のページが1つのデッキのように見える
point: 取締役会の準備は毎四半期同じ週に必要になる。だから自動化する価値がある
note: 解説メモの推測：出力の直しがほとんど出なくなってから定期実行にするのが安全と考えられますが、記事は切り替えの条件を示していません。
note: 自動実行の前に、出力を人が確認する担当と期限を決めておく、という案が解説メモの活用案3にあります（これも推測）。

## 記事に==書かれていないこと==を知っておく
lead: 自分の資料に当てはめるときに、自分で決める部分
- **プラグインが使えないとき**：管理者がプラグインを管理していて使えない場合は、そのステップを飛ばしてよい。以降の内容はプラグインを必要としない
- **値は書かれていない**：重要性の閾値の具体値、CFO の表現、スキルの中身は記事に出てこない
- **画面操作は書かれていない**：コネクタの接続手順と、/schedule の細かい設定は記事にない
- **人の役割は残る**：聴衆の疑問の予測と、基準の設定は人が決める
point: 記事は型を示すだけ。自分の値は自分で入れる
note: この節は解説メモの「注意点・限界」と、FAQ の3番（プラグインが使えないとき）に基づいています。

## まとめ：まず==自分の担当1件==で試す
1. **3枚を名指しする**：ヘッドライン・ドライバー・見通しの名前と役割を依頼文に書く
2. **実例と基準を渡す**：前四半期のデッキをフォルダに入れ、繰り返す値はプロジェクトの指示に保存する
3. **段階を踏む**：手作業で固め、スキルにし、最後に /schedule で定期実行する
> 最初は、元のワークブックの数字とスライドの数字を手元で1回突き合わせると安心です（解説メモの補足）。
note: 解説メモの活用案1（財務・経理の担当者の視点）に沿った締めです。
