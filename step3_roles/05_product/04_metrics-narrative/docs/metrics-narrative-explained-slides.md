# Coworkで数値の「なぜ」を<br>書かせる手順
subtitle: メトリクスのナラティブ化：初めて読む人向けの解説
badges: [技術・ハウツー, Claude Cowork, 初学者向け]
note: 元ページは Claude Academy のユースケース「メトリクスのナラティブ化」。この資料は、その解説メモをもとにしています。
---
<!-- slide: points -->
badge: 全体像
## この資料で分かること
lead: 毎週の「なぜ数値が動いたのか」を、Coworkに下書きさせる流れ
- **ねらい**：数値が動いた理由を、文章（ナラティブ）にまとめさせる
- **材料**：CSV、先週のナラティブ、チェンジログを1つのフォルダに置く
- **頼み方**：1つの依頼文に、異常探しから2つのチャートまで入れる
- **育て方**：スキルにして、毎週月曜の自動実行まで進める
point: 1回頼んで終わりにせず、スキルにして毎週回すところまでが一連の流れ

badge: 用語
## 先に知っておく言葉
lead: 【補足】解説メモの補足による説明です（本文に定義はありません）
- **ナラティブ**：「何が起きたのか、なぜなのか」を説明する文章
- **アクティベーションファネル**：利用者が使い始めるまでの段階を並べたものと考えられる
- **セグメント化**：プラン、プラットフォーム、サインアップ元で分けて要因を特定すること
- **チェンジログ**：同じ期間にリリースされた内容の記録
- **スキル**：やり方をまとめて呼び出せるもの。`/metrics-review` がその例

## 準備は、==3つ==
lead: つなぐ → 置く → 残す
```steps
style: cards
items:
  - icon: "🔌"
    title: コネクタを設定
    desc: カスタマイズ → コネクタ。権限とアクセスは自分で管理する
  - icon: "📁"
    title: フォルダに集める
    desc: CSV、先週のナラティブ、チェンジログを1つのフォルダに入れ、Coworkに指定する
  - icon: "🧠"
    title: プロジェクトを作る
    desc: 毎週書くなら、そのフォルダから。定義・指示・記憶が紐づいたままになる
```
point: Coworkは、ナラティブとチャート画像を同じフォルダに書き戻す

<!-- slide: steps -->
badge: 依頼
## 依頼文は、==1文で5つ頼む==
lead: 今週のアクティベーションファネルの例
```steps
style: circled
items:
  - icon: "🔍"
    title: 異常探し
    desc: 動いたステップをファネル全体から探させる
  - icon: "🧩"
    title: セグメント化
    desc: プラン、プラットフォーム、サインアップ元
  - icon: "🔗"
    title: 照合
    desc: 同じ期間にリリースされた内容と突き合わせる
  - icon: "📊"
    title: チャート2つ
    desc: 論拠を証明するものだけに絞る
  - icon: "📝"
    title: ナラティブ
    desc: 何が起きたのか、なぜなのか
```
point: 切り口、照合先、出力の形まで、先に指定しておく

badge: 工夫
## 依頼の6つの工夫
| 工夫 | 何のため |
|---|---|
| 根拠を求める | 最初に気づいた指標に固執せず、動いたステップを探させる |
| セグメントを指定する | 変化の大部分を説明する1つのセグメントを指させる |
| 変化した内容と照合する | 相関関係を、チームが行動できる因果仮説に変える |
| チャートの数に上限を置く | ビフォーアフターとセグメント分割に絞る |
| 手本を追加する | 構成と文体を自分に合わせてもらう |
| 不確実な点の指摘を頼む | 下書きで最初に確認すべき箇所が分かる |

badge: 運用
## 育てて、回して、共有する
lead: 1回の依頼で終わらせない
```steps
style: cards
items:
  - icon: "🛠️"
    title: スキルにする
    desc: これまでの作業をスキルにするか、フィードバックで /metrics-review を編集。数分の会話でよい
  - icon: "⏰"
    title: 自動で実行
    desc: /schedule で設定。例は毎週月曜の午前7時、週次で10%以上動いたものを指摘
  - icon: "🤝"
    title: 共有する
    desc: どのPMでも同じ構成で答えられ、誰の数値でも一貫したレポートになる
```
point: プラグインのスキルは、あくまで出発点

## つまずく所と、本文に無いこと
- **プラグインが使えない**：導入の手順は飛ばせる。ただし代わりの進め方は本文に書かれていない
- **因果は仮説**：チェンジログと照合しても確定ではない。自信がない部分から確認する
- **本文に無い**：CSVの列、チャートの種類、チェンジログの書式、スケジュールの制限
- **出典**：[解説メモ（README）](../README.md)・[原本ページ](https://academy.claude.com/ja/use-cases/metrics-narrative)

## まとめと、次の一歩
1. 材料を1つのフォルダに集め、Coworkに指定する
2. 異常探し、セグメント、照合、2つのチャート、ナラティブを1文で頼む
3. 「自信がない部分」から確認し、気に入った進め方をスキルにする
4. 毎週の説明が決まっているなら、自動実行にする
point: 次の一歩：自分の仕事で渡せる3種類のファイル（数値、前週の文章、変更の記録）が何にあたるか、書き出す
