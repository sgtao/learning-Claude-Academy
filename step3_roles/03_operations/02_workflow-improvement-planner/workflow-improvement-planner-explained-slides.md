# ワークフロー改善プランナー<br>Claudeと業務改善を始める手順
subtitle: Claude Academy のユースケースを、初めて読む人向けに解説

badge: WHY
## 何を学ぶページか
lead: 改善したい業務を、Claudeに伝わる形で整理する
- **目的**：ワークフロー改善の機会を整理するテンプレートをClaudeに作らせ、記入結果を渡して改善策を設計してもらう
- **整理する5つの観点**：現状／課題・ボトルネック／インプットとアウトプット／成功の状態／制約
- **題材**：記事の例は非営利団体。==自分の仕事に読み替えて==使う（【補足】他の職場への適用は本文には書かれていない）
- **ねらい**：実用的な解決策の設計に必要な情報を、すべてClaudeに渡せる状態にする
note: 記事の例は非営利団体向けです。他業種への適用は本文に書かれておらず、読み替えは解説メモの推測にあたります。

badge: HOW
## 進め方は、==6つの手順==
lead: 作らせる → 記入する → 渡す → 資料化する → 現実に合わせる → 続ける
```steps
style: cards
items:
  - icon: "1"
    title: 作らせる
    desc: 質問を投げかける記入式のアーティファクト（計画テンプレート）を依頼する
  - icon: "2"
    title: 記入する
    desc: 自分の業務を具体的に書く。実物のファイルがあれば添える
  - icon: "3"
    title: 渡す
    desc: 回答を渡し、課題への対応・有用な機能・手順・テンプレートや例を提案してもらう
  - icon: "4"
    title: 資料化する
    desc: サンプルプロンプト、テンプレートファイル、MCP接続の説明、ガイドを作ってもらう
  - icon: "5"
    title: 現実に合わせる
    desc: 無料ツールのみなどの制約を伝えて、簡素化を頼む
  - icon: "6"
    title: 続ける
    desc: 会話を続けて、洗練・拡張・掘り下げをする
```
point: テンプレートは答えを出す道具ではなく、現状を正確に伝える道具
note: 6つの手順は、記事にある4つの依頼文と、会話を続けるという最後の一文を順に並べたものです。

badge: TOOL
## Claudeが作るフォームの中身
lead: 複数ステップで記入でき、最後にClaude向けのプロンプトを書き出す
- **セクション**：特定、現状、課題、インプット/アウトプット、制約、技術的詳細、意思決定ポイント、指標、追加コンテキスト、レビュー
- **進捗トラッキング**：視覚的な進捗バーとパーセンテージ表示
- **条件付き入力**：選択するとテキストフィールドが表示されるチェックボックス
- **ナビゲーションとエクスポート**：戻る/続けるボタン。コピーまたはダウンロードできるプロンプトを生成
- **食い違い**：画像の説明文は「9つ」、本文は「10のセクション」。どちらが正しいかは本文からは決められない【推測】
note: 本文の箇条書きは10項目で、最後のレビューを数えるかどうかの差かもしれません（推測）。

badge: TIP 1・3
## 具体的に、==正直に==書く
lead: 弱い書き方と強い書き方を並べると、違いが分かる
| 観点 | 弱い書き方 | 強い書き方（本文の例） |
|---|---|---|
| 業務の規模 | 月次レポート | 毎月5日までに作成される15ページの寄付者レポート。開発ディレクターが8時間、3つのスプレッドシートから作成 |
| 課題の中身 | とても時間がかかる | Salesforceから200件の寄付者記録を手作業でExcelにコピーし、それぞれを再フォーマットする |
point: 具体性が、Claudeが実際の規模に合う解決策を設計する手がかりになる
note: 弱い書き方として挙がっているのは、月次レポートとだけ書くことと、とても時間がかかると書くこと。強い書き方は本文の例そのままです。

badge: TIP 4
## 速度以外の==4つの観点==
lead: スピードだけでなく、次の箇所にも目を向ける
```steps
style: circled
layout: grid
items:
  - title: 品質の低下
    desc: 例：手作業でのデータ入力中にミスが発生する
  - title: 属人化
    desc: 知識が特定の人に閉じ込められている。例：サラしかこのやり方を知らない
  - title: スケーリング
    desc: 例：50件のクライアントには対応できるが、100件になると破綻する
  - title: ストレスのピーク
    desc: 例：理事会の直前はいつも慌ただしい
```
point: 4つの観点の洞察が、より良い解決策につながる
note: 4つの観点と例は、すべて記事の記述です。

badge: TIP 2・5
## 実物を添え、つなぐ前に準備する
lead: Claudeが実際の内容を見られるほど、提案は良くなる
- **実物をアップロード**：匿名化したサンプルレポート、現在使っているテンプレート、例となるデータ。テンプレートにその旨も書く
- **MCP接続を先に有効化**：Google Drive、Gmail、Google Calendarを使う業務は、Claudeと作業する前に有効にする
- **接続の効果**：手作業のファイルエクスポートが不要になり、Claudeがシステムに直接アクセスするワークフローを設計できる
- **制約を伝える**：無料ツールのみ、技術的な専門知識がない、AI経験が浅い。この3つを伝えて簡素化してもらう
note: 利用に必要なプランや料金は、本文には書かれていません。

badge: CAUTION
## 試す前に知っておくこと
lead: 本文に書かれていないことは、自分で補う
- **書かれていない**：料金やプラン、匿名化の具体的な方法、提案が合うかを確かめる方法
- **例は非営利団体**：他の職場へ当てはめられるかは、本文からは分からない
- **画像は未確認**：アーティファクトの画面画像の中身は、根拠にできていない
- **【補足】小さく試す**：まず1つの業務で試し、合わなければ理由を伝えて頼み直す方法が考えられる【推測】
note: 解説メモの注意点・限界の整理です。最後の項目だけが解説メモの補足（推測）で、本文の記述ではありません。

<!-- slide: summary -->
## まとめ：まず1つの業務で
1. ==作らせて、書いて、渡す==：テンプレートで現状を整理し、完成した内容をClaudeに渡す
2. ==具体的に、正直に==：規模・時間・件数と、非効率の中身まで書く
3. ==実物とつなぎ先==：匿名化した実物を添え、必要なMCP接続は先に有効にする
4. ==現実に合わせる==：制約を伝えて簡素化し、会話を続けて整える
point: 自分の仕事を1つ選び、本文の例と同じ水準まで書くところから始める
note: 最後のpointは解説メモの活用案と深掘りの質問に基づく提案で、本文の記述ではありません。
